## 0. Why, and what is already known
- The dashboard section "Heat-Soak Carryover" (payload `heatSoakCarryover`, built by `_heat_soak_carryover` in `compute_summary_arrays.py`) takes every consecutive chronological pair of LOGGED drives with pack temperature at both ends, bins them by the parking gap `gap_h = start(next) - end(prev)`, and reports per gap bin the median shed and the median retained above-ambient fraction `(T_start_next - T_amb_next) / (T_end_prev - T_amb_next)` (ambient: the manual driving-time field of the next drive; 706 pairs, 593 with ambient), plus a Newtonian soak time constant tau by Sen's slope on ln(retained) versus gap through the origin.
- The pair construction assumes the car stood still between the two logged drives. The cloud odometer shows that it did not always (registered result `analyses/M729_cloud_gaps.csv`, 716 gaps between consecutive logged drives): 508 stationary_consistent, 72 driving_observed (1,808 km), 26 odometer_increase_only, 105 uncertain, 1 export_break, 4 no_cloud_data. By the published gap bins the share of gaps with definite unlogged driving (driving_observed + odometer_increase_only) is 5.3 % (0-1 h, n 379), 11.8 % (1-3 h, 110), 14.6 % (3-6 h, 48), 32.0 % (6-12 h, 75), 28.2 % (12-24 h, 78), 46.2 % (24 h+, 26); counting "uncertain" 18.7 / 30.0 / 27.1 / 50.7 / 43.6 / 53.8 %.
- An unlogged drive between the pair re-heats the pack and resets the cooling clock, so for a contaminated pair the retained fraction is not "heat retained from the end of the first logged drive": the true initial excess at the start of the cooling interval is unknown. Such a pair cannot be corrected, only excluded. The expected direction (a priori, stated as an expectation, not a test) is that contamination raises the retained fraction at long nominal gaps and biases tau upward.
- Cloud detection is imperfect (M739: 84 % of logged drives are detected by the cloud, 90 % among those with cloud coverage; 21 dates have no export rows): a gap labelled stationary_consistent can still hide unlogged driving, so the cleaned set below is "cleaner", not clean.

## 1. Constraints
- Report-only. No change to `summary_arrays.json`, any payload key, the dashboard, `drive_master.csv` (MD5 d514d6009d6d9a0a168ad4fb09b9bb98, asserted before and after) or any winter-frozen file (M726). Raw files read-only. Outputs: `analyses/M751_*.json` and one aggregate CSV, aggregates only (public repository: no coordinates, no per-day cloud tracks; per-pair rows carry file names and class labels only, as `M729_cloud_gaps.csv` already does).
- The M729 gap table is a registered input pinned by file sha256 (recorded in the tool and the CHANGELOG); a mismatch stops the tool (exit 3, nothing written).
- Language: cloud-derived classes are "estimated / reconstructed"; unlogged means no OBD record, not no driving; the result is a sensitivity of the published carryover, never a correction; "contaminated" is a label of the cloud class, not a measured fact about the pack.

## 2. Data and eligibility
- Pairs: exactly the pairs that `_heat_soak_carryover` builds (same adjacency, same `gap_h >= 0` rule, same pack-mean `pm_end`/`pm_start` from `_battery_temp_traj`, same ambient from `summary_config.json ambientByDrive`). The tool re-implements the pairing loop only to keep the file names, and a control (V0) asserts that its all-pairs bins and tau equal the published `heatSoakCarryover` block leaf by leaf (STOP otherwise).
- Join: each pair `(prev file, next file)` is matched to the M729 gap row with the same two files. A pair without a row (outside the export span, or adjacency differing between the two tables) gets class `no_cloud_row`; the number of such pairs and the reason are reported.
- Class sets: **S** = stationary_consistent; **D** = driving_observed or odometer_increase_only (definite unlogged movement); **U** = uncertain; **X** = export_break, no_cloud_data, no_cloud_row (unknown).
- Sets compared: **A** = all pairs (the published set); **B** = S only ("cleaner"); **C** = A minus D (excludes only definite unlogged movement; U and X stay). B bounds contamination from below, C from above in the other direction; the truth for the pack lies between B and C if the cloud classes are informative.

## 3. Estimands
- E0 control: V0 reproduces the published block (bins: n, nAmb, medShedC, medTEnd, medTStart, medRetainedFrac; tau, half-life, nfit, R2, intercept).
- E1 composition: pair counts by class and published gap bin; share of total gap hours in D pairs per bin; for D pairs the median time since the last cloud movement before the next start (`last_move_to_next_h` of the M729 row) beside the nominal gap, to show how much of the nominal gap was really parked.
- E2 per-bin shift: for each published gap bin with at least 20 pairs with ambient in B and at least 10 arrival days: the median retained fraction in A, B, C and the differences A-B and A-C (percentage points of retained fraction), each with a day-clustered percentile bootstrap interval (cluster key: arrival day, as in the published block `dayArrival`; seed 42, 4000 draws; differences computed within the same resample). Bins below that support report counts only ("not estimable at this support"), never an interval.
- E3 tau: the published tau procedure (Sen's slope through the origin; pairs with ambient, initial excess above 3.0 C and residual excess above 0.5 C; at least 8 pairs) applied to A, B and C; tau, nfit, and the day-bootstrap interval of each and of the differences tau_B - tau_A and tau_C - tau_A. Multi-day gaps stay in, as in the published fit.
- E4 contaminated contrast (descriptive, no interval claim beyond bootstrap): median retained fraction in D alone per bin, labelled "not a heat-retention figure".

## 4. Decision rules (fixed now)
- Per bin (E2): the shift is **material** when the day interval of A-B excludes zero AND |A-B| >= 5 pp; **not distinguishable** when the interval includes zero (the minimum detectable shift, 2.8 times the bootstrap SD, is stated beside it, and absence of a shift is not equivalence); **small** when the interval excludes zero but |A-B| < 5 pp. The 5 pp threshold is the smallest difference that changes the displayed rounded percentage reading of the published forest chart by more than its own bin-to-bin step noise; the Director rules on it.
- tau (E3): **material** when the tau_B-tau_A interval excludes zero AND tau_B / tau_A is outside [0.80, 1.25]; otherwise small or not distinguishable by the same wording.
- Overall: "published carryover is robust to unlogged driving" only if no bin with support and tau are material under both B and C; "the published carryover is sensitive to unlogged driving" if any supported bin or tau is material under B and the same direction holds under C; otherwise "mixed". Method disagreement between B and C is reported, not tuned.
- Whatever the outcome, this milestone changes no displayed figure. A material outcome goes to the Director, who decides whether a labelled sensitivity (not a replacement) is added to the payload and dashboard in a later milestone.

## 5. Falsification and limits
- Falsified (for "unlogged driving does not matter for the carryover"): any supported bin or tau material under B with the same sign under C.
- The class labels come from a lower-biased cloud reconstruction (R1 distance and duration not met, recall about 84 to 90 %): B can still contain contaminated pairs, so B-versus-A is a lower bound on the contamination effect. Parking environment (garage vs open) stays unobserved. The ambient is the manual driving-time value, so long-gap bins sit near or below zero by construction; the study does not change that.
- The 24 h+ bin has 26 pairs in total: it will most likely be "not estimable".

## 9. Rev 2: Director rulings on Rev 1 (override sections 1 to 8 where they differ)
9.1 **Reading of the sets.** B and C do NOT bracket the truth: both still contain undetected contamination (cloud recall 0.84 to 0.90), so both stay biased toward the contaminated value; C is the minimum exclusion, and B also selects on cloud coverage (class S needs odometer end anchors within 60 s). A-B and A-C are reported as **lower bounds on the contamination shift**. "Robust" is replaced by "no material shift detected at this support (lower bound)". If fewer than 3 gap bins are supported the overall result is "not established". The U and X shares and the month mix of B versus A are reported (coverage selection).
9.2 **D sub-sensitivity.** D1 = D pairs with `moved_km` >= 1.0 (odometer_increase_only rows include moves of about 0.2 km that cannot reheat the pack); set C1 = A minus D1 is reported beside C.
9.3 **E4 / S-versus-D contrast.** Descriptive only, with a day-bootstrap interval, plotted-by-table against `last_move_to_next_h`, labelled "a class difference confounded by season, time of day and end temperature, not a contamination effect and not a correction".
9.4 **tau.** The E2 medians are the primary comparison. The fit keeps only pairs with residual excess above 0.5 C, which conditions on the outcome, so n before and after each filter is reported per set. Materiality of tau is judged on the decay rate k = -slope (finite for every draw; k <= 0 means no decay), as the ratio k_A / k_B outside [0.80, 1.25] with the interval of k_B - k_A excluding zero; draws with k <= 0 enter the interval as they are (tau reported as unbounded). An E2 sensitivity restricted to initial excess above 3 C is added (the ratio is unstable near zero excess; long bins sit at the ambient-reference floor). The relative shift (A-B)/A is reported beside the absolute shift.
9.5 **Clustering.** Arrival day is primary (as in the published block). Departure-day and ISO-week clustering are reported as sensitivities (adjacent pairs share a drive; multi-day gaps span days). The pair midpoint is not used.
9.6 **Join.** On the ordered (prev, next) tuple. Assert file names are unique in both tables and `|gap_h(master pairing) - gap_h(M729)| <= 0.01 h` (this also catches timezone or clock mismatches). Mismatches go to `no_cloud_row` with a reason code (dropped timestamp, overlap with gap_h < 0, outside the export span). The reconciliation of the 716 M729 gaps against the 706 published pairs is reported.
9.7 **Thresholds.** 5 pp is recorded as a judgement threshold (the "step noise" justification of section 4 is dropped); the floor of 20 pairs and 10 days stays. Materiality wording of sections 4 and 5 is read with 9.1.
9.8 **Audit.** A Sonnet blind audit is enough because nothing displayed changes. Any later payload or dashboard step needs a new Director ruling; an article figure would need an Opus audit and Andrii's sign-off. `needs_andrii_signoff`: false.
