## 0. Verified state (read from the repository)
- `S.evTraction.runMax` = {km 5.21, unassistedKm 1.63, durationS 333, peakKmh 66, meanKmh 56, driveType mixed, file `20260824_212048.csv`, label}. The run is the longest contiguous engine-off interval of `_ev_metrics` (`compute_drive_summary_v6.py`): 1 s grid, nearest sample within `ENG_ALIGN_TOL`, state = rpm <= 400 debounced by `EV_DEBOUNCE_S` = 3 s on known samples, standstill inside a run does not end it, distance integrated on the grid and scaled by the odometer factor k.
- The raw channels exist in the drive CSVs (speed, engine rpm, [BMS] pack current and voltage, [VCM] HV coolant temperature, engine coolant temperature, accelerator pedal D, motor rpm and torque). No trace of any drive is published anywhere in the payload today; a trace needs a new payload.
- The logger cadence differs by drive (`cadence_regime.csv`, fast about 0.9 s per current sample, slow about 3 s); traces are drawn only from fast-polled drives so that a 1 s grid is not mostly interpolation.

## 1. Estimand and nature of the block
Three single-drive illustrations, each a window of logged channels on the 1 s grid of the master's own alignment (nearest sample within tolerance, gaps left as gaps, never interpolated across a gap larger than 3 s). They are descriptive examples chosen by a fixed rule, not estimates, averages or typical cases; the page says "one drive, chosen by rule R, not an average". No interval, no test, no new verdict, no figure enters the article.

## 2. Selection rules (frozen before any result)
Common eligibility for T7 and T9: canonical-clean drive (`ens_outlier_v2` false), cadence regime fast, coverage of every channel the trace draws at least 95 % of grid seconds inside the window, no flagged channel (`ev_valid` style gates not required for T7/T9), window fully inside the drive.
- **T8 engine-off record** (item 8): the run named by `S.evTraction.runMax.file`; no choice involved. Window = the run (as detected by the master's rule, reproduced by importing the master's constants and `_ev_debounce`) plus 30 s before and after. Channels: speed (km/h), engine rpm. Known answers (STOP on a miss): the detected longest run has duration `runMax.durationS` seconds and, after the odometer scale k, distance `runMax.km` to 0.01 km; every rpm in the run is <= 400 on known samples.
- **T7 rotation, generation and combustion** (item 7): candidate windows are the 300 s windows that start 30 s before the first engine start of a drive (first grid second with rpm > 400 after at least 30 s of known rpm <= 400), eligible if within the window the battery both discharges (pack power > +1 kW) and charges (pack power < -1 kW) for at least 20 s each while rpm > 400 (so the page can show both signs while the engine turns). Among eligible windows the one whose count of seconds with rpm > 400 is closest to the median over all eligible windows is chosen; ties by the earlier date. Channels: engine rpm with the 400 line, pack power kW (discharge positive, `Id * V / 1000` as the master pairs it), engine coolant temperature (C), and the logged engine-load proxy only if present at coverage >= 95 % (otherwise omitted, never imputed). Combustion is not inferred from the trace; the page keeps "Engine speed above the 400 rpm cutoff" and "Combustion inferred from boost" beside it as separate claims.
- **T9 power burst** (item 9): per eligible drive take the peak 1 s discharge power (kW, 1 s grid, after the master's pairing) and its time; the chosen drive is the one whose peak is closest to the median of the per-drive peaks over eligible drives (ties earlier). Window = peak time minus 30 s to plus 30 s. Channels: speed, accelerator pedal D (%), pack power (kW), engine rpm. Annotations are computed, never typed: the time and value of the peak, the time the pedal first exceeds 10 % in the window, the time engine rpm first exceeds 400 in the window (or "not in the window").
- The three drives, dates and window starts are written to the payload with the selection counts (eligible drives / windows, the median used), so a reader can see how much the choice rested on.

## 3. Method
- New tool `tools/example_traces.py` (the only writer of `S.exampleTraces`; additive splice with a stamp, allow-list `/exampleTraces`), reads raw bytes through the master's `_prep_bytes`, `_series`, `_asof` and constants; every `open()` uses `encoding="utf-8"`. Values rounded to 2 decimals (speed, rpm, power, temperatures), time in integer seconds from the window start; a gap second is `null`. No file name beyond the drive date and a day label; the file name is kept in the provenance block for the audit.
- Provenance: master MD5, raw sha256 of the three drives, script sha256, spec Rev, selection counts.

## 4. Decision rules and gates (frozen before any result)
- G1 known answers for T8 above; G2 selection reproducibility: the tool run twice gives byte-identical output; G3 partition and alignment: for each trace every plotted channel value equals the master's aligned value at that grid second (reproduced blind by the audit from raw bytes at 1e-6 for the values before rounding); G4 isolation diff: only `exampleTraces` and its stamp change; G5 payload below 60 kB; G6 language gate, semantic gate, `release_check.py`, CI test list, `validate_jsdom.js`; G7 view test (`test_example_traces_view.js`): three traces drawn, the 400 rpm line in T7 and T8, annotations present and bound to the payload, "chosen by rule, not an average" printed, no forbidden wording.

## 8. Director review (Rev 1: revise) and applied changes (Rev 2)
- R1 (Q1): median rules accepted, no fixed date. T8 is labelled "longest engine-off run in the log (a record)", the extreme case, not an example of the usual run.
- R2 (Q2): acceptable only with the denominators shown: the payload and the page give the number of candidate windows (first engine starts), the number eligible (both signs) and the median used, so the reader sees the share of first-start windows that show both signs. The example shows the claim; it does not test it.
- R3 (Q3): acceptable pending Andrii (the repository is public; 1 s speed traces with dates are new personal data). Rev 2 therefore shows relative seconds only (no clock time) and the drive date at most as a month; the exact date and the file name stay in the provenance block for the audit. Whether the page shows the month, a coarser label or nothing is the owner's decision, asked before implementation.
- T7 binding: pack charging while rpm > 400 can be regeneration. A charge second counts toward the "both signs" eligibility only when the logged motor torque is >= 0 (the motor is not braking; if motor torque is not logged in the window the window is not eligible); speed and motor torque are drawn in the panel. Charging is never worded as generation.
- G1 (T8): the 3 s debounce allows raw rpm > 400 blips. The known answer is "no debounced engine-on second inside the run" and the number of raw rpm > 400 seconds inside the run is printed. The +-30 s margins are clipped to the drive bounds; the trace is labelled slow-polled if the drive is slow; `release_check` asserts T8 file == `S.evTraction.runMax.file`.
- T9 binding: eligible peaks require the logged accelerator pedal D > 10 % in at least one of the 5 s before the peak and speed >= 80 km/h at the peak (the lower edge of the 80-120 band of the section it sits in); peaks within 3 s of a gap in any drawn channel are excluded; the page prints candidates (drives with a peak), eligible and the median peak.
- Ingestion: the selection is FROZEN: the payload records master MD5, N candidates, N eligible and the median; the tool has `--check` that reports "selection stale" when the master differs (disclosed on the page by the recorded drive count), and an ingestion stage is not added (a later ingestion does not change the shown examples). Re-selection is a new milestone.
- Gates added: the blind audit repeats the selection itself from the rule text (candidate, eligible, median and the chosen drives/windows must agree); the view test checks that gaps are drawn as breaks; an M795 language rule is added to `language_gate.py`.
- Wording: "one drive, chosen by a fixed rule; not an average or representative drive"; "engine rotation above the 400 rpm cutoff", never combustion; combustion only through the boost-class proxy (app-calculated); pack power "logged pack power (from logged current x voltage)"; "engine coolant temperature (thermal state, lags)"; never "typical", "representative", "measured", "the engine charges the battery".
- needs_andrii_signoff: true (R3 only).
