The ruling asked for a reported interval = union of the bootstrap CI and the 4.58-5.43 Ah method range. 2. **Method-range list (fixed, pre-registered; amendment allowed because no code exists).** Added to v3's list, with exact definitions taken from the audit's script, re-implemented here (not copied): (i) non-overlapping SoC-excursion windows of 5, 10 and 15 pp: a window starts at a SoC sample and ends at the first later sample whose SoC differs by at least the target within 600 s, lasts at least 10 s, and rejects windows that bridge a current gap > 5 s, a SoC gap > 5 s, or a SoC jump > 2 pp within <= 5 s; window endpoints are integrated exactly under linear interpolation of the logged samples; windows are non-overlapping within a threshold and data are reused across thresholds (disclosed); raw SoC = 0 artefacts never define support bounds. (ii) charge model `Q_window = Qscale x dSoC/100 + b x hours` and energy model `E_window = Kscale x dSoC/100 + bE x integral(V dt)`, fitted SEPARATELY, residual terms labelled model terms (not sensor drift, not degradation). (iii) whole-drive fits and direction-only fits (net-direction fraction >= 0.8) as additional sensitivities. (iv) matched-support lag scenarios -2 s / 0 s / +2 s: only windows valid at all three lags (identical support), reported as SCENARIO sensitivity, never as a CI; the lag is frozen and never tuned on the evaluation data; lag cannot be identified from round-robin logs, only the fast 3-PID Ready-mode run can bound it. The union of everything is the `methodRange`; adding a further entry needs another amendment.
3. **Chronological folds in test (b).** The offset-vs-I2R 2x2 design keeps day-blocked folds (>= 5, scale and R fitted inside each training fold) AND adds two chronological folds (earlier-to-later and later-to-earlier at a date cut fixed before evaluation, v3's 2026-08-01 is kept), reported with held-out RMS per model; the cut is not optimised. Season and logging regime are confounded with the cut: reported as descriptive.
4. **Pre-Ready zero-current check (F14, descriptive).** If the logs contain stationary samples with the HV system at (near-)zero current before Ready mode, report the median current there with a day-clustered CI as a sensor-zero consistency check; it is not used in fitting. If no such samples exist, the leaf says "no samples", not 0.
5. **EFC / FCE / GTC table (F16, S3).** `capacityBasis.exposure` carries five formulas, each from `ah_throughput.csv` or the master, with reference named: discharge EFC `Ed/Eref` (energy), bidirectional FCE `(Ed+Ec)/(2 Eref)`, GTC `(Ed+Ec)/Eref` (twice FCE, not a conventional cycle count), charge-throughput EFC `(Ahd+Ahc)/(2 Qref)`, SoC rainflow EFC (logged scale, unchanged). The legacy ML feature `efc_per100km` (it is GTC) is documented, never renamed. Changing the reference scales counts inversely, with unchanged physical throughput.

## Rev 1a (implementation, 2026-10-11; owner sign-off "go as you recommend" for v4 and an additive first step; no article sign-off)
Implemented in M403 (additive; no headline, master column or other payload leaf changes): registry (`CAP_AH_RATED` documentary entry in `constantProvenance`, registry list in the block), estimators B / reverse / A / windows / whole-drive / direction / matched-support lag / chronological, tests (a), (d), (g) and the block `capacityBasis` with its artifact stamp, stage `capacity_basis` after `cadence_regime`, harness `tests/synthetic/test_capacity_basis.py`, blind audit of the pipeline-written numbers (`analyses/M403_audit/`). Both steps are additive; no headline switches before your acceptance of the numbers.
Deviations and findings (all script-verified, none typed):
1. **Window definition.** The audit-package windows start at an arbitrary sample and end at the first sample 5/10/15 pp away. The synthetic harness showed that chaining such windows biases dSoC (a window starting right after a turnaround spans 0.5 pp less true SoC than its reading says; about -7 % at 5 pp). The anchored definition used for W5/W10/W15 requires both ends to be threshold crossings of the logged SoC in the SAME direction (start re-anchored at the last same-direction crossing into the level exactly `target` away from the end); on noise-free synthetic drives it recovers the truth (5.000 Ah). The audit-package definition is kept as the pre-registered sensitivity `W10_literal` (target 10 pp) with its own lag scenarios.
2. **Lag sensitivity depends on the window definition.** The literal definition reproduces the deep audit's matched-support lag numbers exactly (1,014 windows; -2 s / 0 s / +2 s = 4.6611 / 4.9603 / 5.1791 Ah); with anchored windows the same scenarios give 4.926 / 4.920 / 4.858 Ah. Both sets are in the block and in the method range; neither is a CI; the lag remains unidentifiable from round-robin logs.
3. **Method-range list.** v3's "5-minute windows (post-hoc)" and "fast-leg (|I| >= 30 A) / slow-leg strata" are replaced by the audit windows, direction-only fits and fast/slow LOGGING-REGIME strata (the leg-based strata of the exploratory study are not defined on the pipeline's data model). Adding or removing an entry needs an amendment; this is that amendment.
4. **Test (a) power rule (simplified MDE).** An equivalence test whose own 90 % interval half-width is not smaller than the margin cannot conclude equivalence even at zero difference: it is labelled "not powered" and defaults to the conservative outcome (escalate). The harness shows the test can fail (a 5.0 vs 6.5 Ah split is not equivalent).
5. **Population.** `ens_outlier_v2` explicitly False with usable current and SoC series: 540 drives on 108 days; the 12 NaN-flag drives have no usable series (test (d): "no effect, k = 0", not a pass). Extraction guard aligned with the written definition (more than 20 current samples, at least 10 SoC samples): the blind auditor's 540 vs the first implementation's 539 was one drive with 44 current samples, now included; point estimates unchanged.
6. **Blind audit tolerance.** Reproduction within 1 % for point estimates (B, kWh, offset, reverse, A agree to four decimals; anchored W10 4.9191 vs 4.9145 = 0.09 %, caused by the documented ambiguity of how a failed window advances; CI endpoints differ by <= 6e-4 Ah, bootstrap randomness).
7. **Wording to correct in M404.** The repository texts call the Article-10 5.0 Ah figure a "per-cell" figure; the disclosure sheet (X-Trail e-POWER, model T33, read visually 2026-10-11) says "Rated capacity 5 Ah" with the explanation "capacity (Ah) is divided energy (Wh) by the nominal battery voltage" and does not say per cell, nor the drivetrain. `CAP_AH_RATED` carries the sheet's own wording; the old sentence is replaced in M404 with an old-wording rule.

## Rev 1b (M404, 2026-10-11): remaining pre-registered pieces, Director ruling, deviations
Implemented as additive leaves of `capacityBasis` (no headline, master column or other payload leaf changes): `shadowEligibility`, `offsetModelTest` (b), `levelTest` (c), `keyOnTest` (h), `zeroCurrentCheck`, `exposure`; code in `tools/capacity_tests.py`, harness `tests/synthetic/test_capacity_tests.py` and `test_m404_wording.py` (both in CI); blind audit in `analyses/M404_audit/`; Director ruling `analyses/M404_director_ruling_2026-10-11.md`.
1. **Shadow eligibility** reuses the pipeline's own `_domain_rules` and two-pass offset iteration; at the legacy 2.1 kWh scale it reproduces the master's `f_domain_2p` exactly (known answer). Result under the estimated scale and both thresholds: 0 flips; a flip fails the `semantic_gate` check (escalation). The canonical exclusion is the hard physical rules only (`ens_outlier_v2 = ens_invalid = f_domain_2p`), no ML in the decision.
2. **Test (b)** on drive-level data (master net energy vs the SoC drop, a loss term from the I2 integral on the kWh block's I/V pairs, temperature term): folds = whole calendar days (5, seeded permutation) with scale and R fitted inside each training fold, two chronological folds; acceptance (i)-(iv) as v3; (ii) on the 90 % interval (harmonised with (c), outcome unchanged on the 95 % interval); VIF on standardised columns. Outcome: the I2R model lowers held-out error at both scales and R is stable across folds, but the offset and I2 terms are not separately identifiable and the remaining offset is not equivalent to zero: **dual report only, offset basis unchanged**. The drive-level scale in this regression is attenuated by SoC reading noise and is not comparable with the event estimate.
3. **Test (c)**: one pre-registered linear slope of the apparent scale on segment-centre SoC, unadjusted and adjusted (mean |I|, temperature, logging regime, engine-on fraction; zero-variance covariates dropped). Outcome wording per the ruling: "SoC-level-associated variation of the apparent scale, attribution unresolved"; Option C stays a pre-registered sensitivity only; the constant scale is an average over the observed SoC distribution.
4. **Test (h)**: adjacency in the FULL master ordering (no bridging across excluded or no-pair drives). The first implementation and the first blind run both paired within a filtered set (bridging); the clarified rule gives the same sample and the same slope in both implementations. The slope depends on the 5 s dt cap of the net-charge integral (blind audit: sensitive to it), so it is descriptive only; strata carry n and intervals.
5. **Zero-current check**: the leading stationary samples have a non-zero median (load), so they are not a sensor-zero reference; no zero reference exists in the logs.
6. **Exposure** (raw Ah and kWh primary; legacy 2.1 kWh, the apparent scale, rated 5.0 Ah and the window-fraction band): `f_min = E_PER_SOC100_EST / 2.1` (identity, tested); the f = f_min end of the band is labelled as such (`windowFractionBand_fMinEnd`).
