## 2. Design
- `_esm_classify(rpm, strict_off=False)`: with `strict_off=True` the 'off' / 'low' edge is `rpm > _ESM_EDGES[0]` (the other edges unchanged); the default call is byte-identical (G0: the stored `engineStateMachine`, `engineDwellSurvival` and the cohort chart are identical on 606 drives, before anything else is built). `_engine_state_machine(dm, raw_loader, frame_loader=None, strict_off=False)` passes the flag; with it the methodology text and `stateEdgesRpm` say 'off rpm <= 400' and 'low (400, 1400)'.
- The Rule block is the FULL block structure (occupancy with its day-clustered intervals, per-state dwell, entries, battery kW, transition matrix), recomputed over the same drives by the stage `engine_state_machine_rule` (`tools/engine_state_machine_stage.py`; placed after `engine_on_blocks` in `tools/ingest_stages.json`). Per-drive sufficient statistics are not cached (the pooled battery-kW and dwell lists are not summable); the stage result is cached as a whole, keyed by the sha256 of the sorted raw-file sha256 list, the source hash of `_esm_grid` / `_esm_classify` / `_engine_state_machine`, and the edges, so an ingestion with no new drive does not rerun it. Season cohorts come from the same function over the cohort subsets, as `tools/regen_seasonal_raw.py` does for the stored chart (cohort partition = `thermal_regime` of `seasonal_drive_master.csv`).
- Payload (additive): `engineStateMachineRule` = `{rule (thresholdRpm 400, boundary gt, state 'off' = rpm <= 400), pooled (the block), byCohort {warm, shoulder, cold}, detail (n drives, n days, seconds moved off <- low, per cohort), limits, provenance (gates, hashes)}`; the stored block is not touched. Option C (changing the stored block) stays rejected.

## 3. Estimands and intervals
Same estimands, drive set and day-clustered intervals as the stored block (the stored block's own bootstrap: per-drive state fraction median with a day-clustered percentile bootstrap, seed 42, 4000 draws); every interval belongs to ONE definition. No stored-versus-Rule contrast is drawn and no difference interval is formed. Cohort views with fewer than 5 calendar days are exploratory (no interval reading). The pooled 'off' share is a share of RPM-supported 1 Hz time on the state grid, not engine-on time.

## 4. Known answers and expectations (pre-registered)
- KA1 (G0): the default call equals the stored block, the stored dwell-survival block and the stored cohort chart, byte for byte, on the 606 drives.
- KA2 (conservation): per drive and pooled, seconds(Rule off) = seconds(stored off) + n(state-grid seconds with rpm == 400.0 exactly); every other state's seconds are identical except 'low' = stored 'low' - n(exactly 400); the transition matrix differs only in the rows / columns of 'off' and 'low'; the engine-on hours of the Rule block = the stored hours - n(exactly 400)/3600.
- KA3 (expectation, not a gate): n(exactly 400 on the state grid) is of the order of the 53 s found on the pipeline grid (same data, different grid); the Rule 'off' pooled share moves by well under 0.01 percentage points; any larger move is an escalation (A3).
- KA4 (synthetic): a trace containing 399, 400, 401 rpm and NaN: 400 is 'off' under the strict flag and 'low' by default; 401 is 'low' in both; NaN stays unclassified (-1); the edges 1400 / 2300 / 3200 stay `>=`.
- Onset sensitivity known answer: the > 300 detector reproduces the stored `engineStartRate` counts exactly (M343 known answer) before the > 400 count is reported; the > 400 events are a subset of the > 300 events (runs can only shorten, split or drop: the M544 taxonomy).

## 5. Conventions of record (`docs/conventions_of_record.md`, written from the code and the M544 / M545 audit notes, without a number)
Pipeline 1 Hz grid; the state-machine grid (different: mean resample, `ffill(limit=3)`, no native ffill); native-row blocks (ffill limit 15 gives up to 16 rows per sample, valid-speed and valid-rpm requirements, speed source: [VCM] vehicle speed where `speed_source` is vcm, else OBD speed); boost handling (negatives stay in n, `maxBoost` floored at 0.0; no valid engine-on boost gives a null hvc entry); the 'last' aggregator; NaN policy per block; strict boundaries; which blocks stay on the stored 300 basis and why. The document states each convention once with the code location, so a blind auditor can be given it without the code.

## 6. Tests

## 7. Display (after the M545 pattern)
`EngineStateMachine` chart (primary and cohort variants) reads `engineStateMachineRule` through a guarded accessor (`rule.thresholdRpm === 400`, `boundary === 'gt'`), cohort views from `byCohort` (never the pooled block; `cohortNoData` unchanged); compare mode keeps the stored chart and is titled 'stored basis (off = rpm < 400)'. The chart title / unit text and the methodology sentence say 'off = rpm <= 400 (strict engine-on boundary)'; `stateEdgesRpm` of the Rule block drives the edge labels (JSX line about 9091). The stored value is quoted at most once per sentence as 'stored basis (off = rpm < 400)', with no arrow, delta or difference interval. Run-length wording is not involved. Dashboard change rule applies (SendUserFile render, one line with the `S.*` keys, sources committed together).

## 8. Language
New `language_gate.py` rules (ledger id M546) retire 'off = rpm < 400' (and 'off rpm<400') as the current definition in the dom and jsx scopes (the stored payload methodology string keeps it, so the payload scope is not used; compare-mode titles carry the 'stored basis' label). Allowed: 'off = rpm <= 400 (strict engine-on boundary)', 'stored basis'. Never: 'correction', 'true' or 'more accurate' off share, a shift presented as a finding, 'significant' for a stored-versus-Rule difference. The audit is described as an audit sample reproduction; if conventions are again resolved by calibration, the report says 'convention-calibrated'.

## 9. Acceptance, falsification, escalation
- A0: G0 byte-identical (own commit before the stage); `drive_master.csv` MD5 `5556a0c6...`; ML16 untouched.
- A1: independent recomputation of the Rule block on the audit sample from the raw files; KA1-KA4 and the conservation identity hold.
