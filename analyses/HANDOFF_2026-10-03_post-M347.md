## 2. Standing workflow (as practised; CLAUDE.md is authoritative)
1. Spec first: pre-registered `analyses/M###_spec.md` (rev 1), committed on the branch ("work in progress: Director review pending").
2. Director review (`research-director`, Opus): returns a compact JSON brief; apply required changes as "Rev 2" appended to the spec; re-review if the changes are structural.
3. Build with scripts; every reported number is written by a script (JSON), never typed from memory. Known-answer tests for new estimators; controls (reproduce the stored value with the UNCHANGED method) before any splice; additive leaf-splice with a deep-diff allow-list (never run `run_pipeline()` / the v6 CLI for routine work).
4. Blind audit (`analytical-auditor`): give it the claim + data path + definitions only (not the author's code or files named `analyses/M###_*`); it reproduces independently. Verdicts so far were confirmed or "partial" with stated method disagreements (reported, never tuned away).
5. Director decision on the audited result (required wording / forbidden wording / headline allowed / sign-off needed).
6. Dashboard rebuild, gates (list in section 6), CHANGELOG entry via `python tools/changelog_draft.py --id M### --title ... --rationale ... --files ...` (prepends; the model writes only the rationale), `python release_check.py`, commit (jsx, arrays, html together), push, `gh pr create`, `SendUserFile` render of `xtrail_dashboard.html` with one line on what changed and which `S.*` keys it binds to.
7. PR merge is done by the agent ONLY when the user says "green" AND all four CI checks (`checks`, `release-gate`, each twice) are `COMPLETED/SUCCESS`, the PR is not draft and `MERGEABLE`: `gh pr merge N --merge --match-head-commit <sha>`, then `git fetch origin main && git tag M### origin/main && git push origin M###`, then `git checkout -B claude/next-milestone origin/main && git push -u origin claude/next-milestone`. Never squash, never force-push.
8. Wording changes always go through a Director string review; the old wording is added to `language_gate.py` RULES with a milestone id (standing M326 rule); REQUIRED-wording checks live in `semantic_gate.py` (A2 block).
9. Sub-agents cannot spawn sub-agents; the main session dispatches them. Write any file a sub-agent must read BEFORE dispatching it (one Director run failed because the spec file did not exist yet). Agents exchange compact JSON briefs (<2 KB).

- Line endings: the repo is `* -text`; always write LF. Python/pandas writers on Windows emit CRLF: run `python tools/normalize_eol.py` after pipeline writes (a CRLF rewrite shows up as a 100k-line diff).
- Tool gotchas learned: (1) the Bash tool collapses double backslashes: regex escapes written through a bash heredoc become control characters (`\b` -> backspace). Use the Write tool for files containing regexes, or build them with `chr(92)`, and check with `grep -c $'\x08' file`. (2) Heredocs containing apostrophes can break the shell; use the Write tool for long text. (3) `VAR=$(cmd),x python ...` expands `$VAR` before assignment; assign on its own line. (4) Background commands are killed when the tool call returns if they use an inner `&`; use `run_in_background: true` with one command chain and a long `timeout` (max 7,200,000 ms). (5) Windows multiprocessing needs `if __name__ == "__main__"`. (6) Python `-` in `hidden` Unicode paths: pass `encoding="utf-8"` explicitly. (7) After a PR merge, `git checkout -B claude/next-milestone origin/main` carries uncommitted work cleanly only if it does not touch files that differ.
