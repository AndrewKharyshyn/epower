# M728 spec Rev 2 (pre-registered before any check and before any winter scoring result): extractor of the observed quantity of the M717 winter prediction P4 (BMS charge-limit register)

Status: Rev 2 after the Director review of Rev 1 (decision "revise", ten changes; record `analyses/M728_director_review_rev1.json`). The review showed that P1 cannot be done faithfully without vendoring and verifying the production park-model pair builder (restart census, ambient reconstruction, the M709 unlogged-use pair flag, the winter diurnal amplitude assumption); P1 is therefore SPLIT OFF to M732 and this milestone covers P4 only. The ten changes that concern P4 or the registry (7, 8, 9, 10) are adopted below; changes 1-6 (P1) move to the M732 spec. No observation after the freeze is used to build or tune anything in this milestone. Author: main session.

## 1. Scope and split
M727 froze the extractors of P2, P3, P5, P7. This milestone writes, specifies and freezes the extractor of P4. Out of scope and still 'not evaluable (extractor not frozen)': P1 (M732: the state chain, its park-model pair builder and flags, the diurnal convention, the free-run rules), P6 (M731: a per-event extraction of the peak charge C-rate with the probe temperature and SoC at the peak) and the realised-ambient P2 band (M731). Until M731 is frozen P2 is the frozen-band reading with the realised-ambient band owed, and no statement that the cold outputs are supported is made. The Director's constraint: M731 and M732 must be frozen before the 2027-02-11 look, else P1, P2-realised and P6 are not evaluable at that look.
The frozen module `tools/winter_extractors.py` (M727) is NOT edited. New code goes into `tools/winter_extractors_b.py` (P4) and `winter_score.py` v3 (dispatch of P4, registry path `analyses/M728_extractor_registry.json`). The M727 registry stays as history; its recorded `winter_score.py` hash no longer matches, so it is superseded, not edited. The M728 registry lists all frozen modules (`winter_extractors.py` unchanged, `winter_extractors_b.py`, `winter_score.py` v3), covers P2, P3, P4, P5, P7, and records the sha256 of the superseded M727 registry.

## 2. Common rules (inherited from M726 and M727, frozen)
Scoring set = clean drives that start after F + 1 h (F = 2026-11-17T19:01:29+02:00); the frozen basis (through 2026-11-09) is never scored; the stratum 2026-11-10 to F - 1 h is reported beside, never primary. Support: at least 10 drives on at least 5 days per cell, else 'not evaluable' and no number. Interval: day-clustered percentile bootstrap, seed 42, 4000 draws, 95 %, days in ascending date order (fixed). Region label: 'interpolation check' inside the temperature range of the frozen basis (coldest pack probe 1.0 C), else 'extrapolation test'. Frozen predictions and parameters are read ONLY from the freeze file and its frozen copies; no live model output.

## 3. P4 extractor
Observed: the BMS-reported charge-limit register (input possible power, kW; BMS-reported register, not delivered power) against the coldest probe and the SoC, from the per-drive sufficient statistics of the exposure frame (`pin_n`, `pin_xty_0..2`, `pin_xtx_00..22`: the normal equations of Pin on [1, Tmin, SoC - 60] over the seconds with Tmin below 20 C, the form of the frozen fit; the frame converts the pre-2026-09-30 horsepower values to kW).
Cell: scoring drives with a probe minimum (`Tlo_min`) below 5 C and `pin_n` > 0. The summed normal equations of the cell are solved; condition number of the summed X'X above 1e8 -> 'not evaluable'. b0 = model-derived register at 0 C and SoC 60 (an intercept of the re-fitted plane, not the logged register at 0 C); at -10 C: b0 - 10 bT. Day-clustered bootstrap by per-day sums over the cell's days (ascending order).
Evaluability: the 0 C statement needs the coldest `Tlo_min` of the cell at most 3 C; the -10 C statement needs at most -5 C (even with data to -5 C the -10 C value is extrapolated 5 C); otherwise that statement is 'not evaluable (no data near the temperature)'. `Tlo_min` is the coldest probe over ALL seconds of the drive, a proxy for the regression seconds (Tmin below 20 C): the cell reports the pin-weighted mean Tmin (pin_xtx_01 / pin_xtx_00) and the number of regression seconds `pin_n`.
Rules (pre-registered): the POINT estimate of b0 inside the frozen interval [32.72, 35.47] kW; the register at -10 C inside the frozen envelope [16.43, 20.97] kW; the day-cluster intervals are reported beside. Region 'extrapolation test' for either statement below the coldest probe of the frozen basis (1.0 C).

## 4. Check, build and freeze (no post-freeze observation)
Built and checked on synthetic frames with planted truth and on the FROZEN BASIS only (day <= 2026-11-09, exactly the 665 prototype keys; the build masks any later row). Pre-registered criteria, written BEFORE the check is run (every run stored; one revision allowed, limited to an implementation mismatch with the documented prototype, with a diff and a new spec Rev; windows, thresholds and rules must not change after the check; a check still failing after that revision means P4 is 'not evaluable (extractor not frozen)'):
C-P4a (fidelity, frozen fit on the frozen basis, drives with `pin_n` > 0, all with Tmin below 20 C): n_s (sum of `pin_n`) within 0.5 % of 89334 and the number of days with `pin_n` > 0 equal to 60; b0 within 0.05 kW of 33.92; bT within 0.01 kW per C of 1.553; the SoC slope within 0.01 kW per SoC point of -1.01; the extractor's seed-42 interval endpoints for b0 within 0.15 kW of [32.72, 35.47] (a pre-registered procedure and Monte Carlo tolerance: the frozen interval came from the prototype bootstrap with another day order and stream). The coldest `Tlo_min` of the basis is reported (1.0 C expected).
C-P4b (descriptive, no tolerance, never the check): the same fit over ALL 717 drives of the frame (any date) is reported as the sensitivity to the key set (the Director noted that the M713 production frame at 696 drives gives 34.04 kW against 33.92 kW on the 665 prototype keys); this run reads post-freeze drives only as a descriptive sensitivity of the FRAME, not of any prediction, and is stored with the check.
Freeze: `analyses/M728_extractor_registry.json`, script-written, per prediction id: function name, version, columns, the freeze file sha256, this spec's sha256 and the `winter_score.py` v3 sha256; `modules` (path to sha256); the superseded M727 registry sha256; the registry's own sha256 is recorded in the CHANGELOG. `winter_score.extractors_frozen(pid)` (v3) reads the M728 registry; P1 and P6 are not listed and stay 'not evaluable'. The registry and the new module join the read-only set of `tools/guard_paths.py`. After the freeze nothing is edited; a change is a new version with a new registry.
