# M567 spec Rev 1 (2026-11-02, before any code): A and C views of the charge-rate risk map use the same timing tiers as the kW view (M550 follow-up, "A/C fallback asymmetry")

Status: PRE-REGISTERED DRAFT for Director review. Tier B (number-changing display). Parent: `analyses/M550_spec.md` Rev 1-2 (tiers cotimed / nearby / late / none, R1-R4, D1-D10), `tools/power_peak_temp.py`, `CRateRiskMap` in `xtrail_summary.jsx`.

## 1. Defect (read from the code and payload at M566)
Since M550 the kW view plots each drive at the T1 sample nearest its peak charge POWER sample with explicit tiers: within 1 s, within 3 s, hollow 3-10 s (late), omitted beyond 10 s. The A and C views still plot x = `T1_at_peak_Crate`, the master's current-peak pairing, which for drives without a T1 sample within 3 s of the peak-current sample falls back to the DRIVE-MAXIMUM T1 (`T1_at_peak_Crate_isFallback`, a temperature from another moment). `powerPeakTemperature.summary.classI` shows 136 of 573 plotted drives (24 %) without a co-timed (<= 3 s) T1 at the current peak, drawn in the A and C views at an unrelated temperature without any marker, while the kW view shows the same kind of drive hollow or omits it. The views therefore apply different pairing rules to the same event metric (audit N07: timing age as part of every event metric).

## 2. Design
- Extractor `tools/power_peak_temp.py` (read-only over raw): per drive, the T1 sample nearest the master's current-peak sample `tPeakI` within 10 s (same `_near`, no interpolation) and its signed age: new fields `T1AtPeakI_10s`, `ageI_any`. Existing fields unchanged. Cache key changes with the extractor hash (`powerpeak_cache/`, git-ignored).
- Payload (additive): `powerPeakTemperature.acViewX` keyed by file: `{x, tier, ageS}` with the SAME tier rule as `kwViewX` (cotimed <= 1 s, nearby <= 3 s, late 3-10 s, none = beyond 10 s or no T1 sample, omitted); `summary.tiersAC` counts per tier and per cadence stratum; `summary.acVsLegacy`: number of drives whose A / C x moves relative to the legacy `T1_at_peak_Crate`, the median and 90th percentile of the absolute move, split by legacy fallback yes / no. `cRatePointsAK` and every existing key unchanged (deep diff = additions).
- Display: the A and C views plot x = `acViewX[file].x` with late points hollow (legend as in the kW view), points with tier none omitted; the caption gives n per tier per cadence stratum for A / C next to the kW counts, plus the generated count of drives that moved relative to the previous convention (the drive-maximum fallback). The x-axis label of the A / C views becomes "Battery temperature, Sensor 1, at the sample nearest the peak charge current (C)". The old fallback is no longer drawn; it stays in the payload and the master (`T1_at_peak_Crate*` unchanged).
- Not changed: the master peak pairing (largest C-rate across the reg / egc / dual channels), the y values, the cohort pooling, the kW view.

## 3. Known answers and expectations (pre-registered)
- KA1 (reproduction, hard gate): for every drive with `T1_at_peak_Crate_isFallback == False` and a cotimed / nearby tier, `acViewX.x` equals the master `T1_at_peak_Crate` (rounded to 0.1). A mismatch STOPS. For fallback drives the tier is late or none by construction (no T1 within 3 s).
- KA2 (rebuild): the rebuilt current-peak timestamp `tPeakI` equals the one stored by M550 for every drive (exact).
- KA3 (tiers): synthetic frames: T1 sample 0.8 s from the peak -> cotimed; 2.5 s -> nearby; 6 s -> late (hollow, value at that sample); 11 s -> none (omitted); no T1 channel -> none; a tie in distance takes the earlier sample; no interpolation.
- KA4 (view): jsdom on the real payload: A and C views draw the late points hollow, omit none points, show the counts; the kW view is unchanged.
- Expectation (not a gate): the 136 legacy-fallback drives split into late and none; the points that move are exactly those drives (counted); fast / slow strata are reported separately.

## 5. Language
Old wording retired by a rule (ledger AUD29-N07): the A / C views plot "the peak-current temperature" without a timing tier, and any text that presents the drive-maximum fallback as the temperature at the peak; allowed: "temperature at the sample nearest the peak charge current (within 1 s / 3 s / 3-10 s)". Temperature channels are app-reported BMS probes (logged, not measured).
