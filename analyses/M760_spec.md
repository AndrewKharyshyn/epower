## 1. What and why
- M749 held X1 back because its source had 431 drives and no day count or day interval. M752 supplies both (418 identity-class drives of 2 km or more, 130 days, day-clustered bootstrap, seed 42, 4000 draws). The Director's M752 decision lists the conditions for a display; this spec turns them into frozen rules.
- Scope: DISPLAY of an already-registered, audited, report-only result as note X1 inside the existing cloud cross-check block (`cloudCrossChecks`), beside X2 (Between-drive logged share). No new estimate, no change to any published figure, to `distance_km`, to the logged-share KPI or to the ODO rule. The cloud odometer is auxiliary; OBD stays primary.

## 2. Payload (additive, carried)
- `tools/cloud_payload.py` gets a new pinned source (`M752_odometer_agreement.json`, sha256 pinned in PINS) and fills `x1LoggedDistance` (today `None`), replacing `x1HeldBack`. Script-written from registered fields only (tolerance 0); strings written in the tool. Isolation: only `/cloudCrossChecks` changes. The block stays registered-corpus carried (717 drives, master d514d600...), same label as X2-X4.
- Fields (from the primary E_int, identity class, 2 km or more): `nDrives` 418, `nDays` 130, median per-drive difference (km) with its interval, relative difference (aggregate) with its interval, coverage (available 584 of 717), selection by month and by length stratum (counts only), integrity counts (negative steps, level excursions with the maximum, jump-excluded drives as the tool counted them), the Rev 2.1 rule note, the E_br and shift sensitivity points (relative difference only, sample sizes), the anchor (n = 1, one-sided), and the registered verdict wording keys. The interval figures displayed are the result file's (the Director wording typed "[1.04, 1.40]"; the file carries [0.01044, 0.01414], i.e. 1.04 to 1.41 percent: the page binds to the file, never to typed text).
- NOT carried or displayed: the absolute cloud odometer, the anchor's cloud value and the cloud-plus-logged value (M749 rule: no cloud odometer value), per-drive rows, any cloud km total, anything that could be read as a replacement or correction of the logged distance.

- Where: directly after the existing `CloudCrossCheckLogging` note in the "Between-drive logged share by month (descriptive)" section, same style (small grey note, dashed rule), bound to `S.cloudCrossChecks.x1LoggedDistance.*` only.

- R1 payload: every X1 leaf equals the registered result file leaf (tolerance 0); the splice changes only `/cloudCrossChecks` (and its stamp inputs); `drive_master.csv` MD5 unchanged; no cloud odometer value and no cloud km in the block (the existing release_check word guard is kept and extended with `cloudLastOdoKm`, `cloudPlusLogged`).

- R3 jump-rule difference: the jump-rule difference (tool 17 versus auditor 7 drives; 418 versus 420 n) is DOCUMENTED, not resolved, in this milestone.
