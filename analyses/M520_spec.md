## Part A - support-restricted refits of the resistance-proxy months coefficient (new analysis)
Estimand: the powerFade S1-design months coefficient (mOhm/month; estimated proxy, one warm-season window, conditional association) restricted to drives whose own resistance-fit sample count is at least 2 x the declared minimum (VREG_MIN_N = 300, so `n_vreg_samples >= 600`; the A1 variant uses its own `a1_n`, per M505 Rev 2 R2).
Cells (registered now, six, no others): A in {A0, A1} x G in {G0, G1, G2}, with C1 (eff_dt_s + coverage_frac) and T0 (linear). Same design matrices, same G2 exclusion rule and same frozen modal grid pair as M514; only the drive filter differs.
Population: M514 paired set F* (G0/G1) or its G2 subset, filtered to the support margin. Expected counts from the M514 payload `supportMarginDescriptive`: 184 drives (G0/G1) and 156 (G2); days computed by the script.
Method: the M514 engine unchanged (`tools/resistance_joint_matrix.py`: day-clustered percentile bootstrap, seed and draw count as in M514 (`SEED`, `NB` in the script); ISO-week, M7 and M14 intervals also reported). The refit reuses `compute()` pieces; no new estimator, so no new known-answer test beyond an identity check: with the filter set to "all drives" the six cells equal their M514 values to 1e-9.
Reporting: slope, day / week / M7 / M14 intervals, n drives, n days, decisive flag, failed-draw share, per cell, in a new key `resistanceJointSensitivity.supportRestricted` (additive; allow-list path `/resistanceJointSensitivity/supportRestricted`). Label: exploratory support-restricted sensitivity; selection into longer, better-supported trips changes the population; calendar, instrumentation and model confounding remain; not an ageing rate; not part of the 54-cell ladder.
Accept / reject: the block is accepted if (i) the identity check passes, (ii) the blind audit reproduces all six slopes and day intervals within 5e-6, (iii) isolation diff clean. The re-audit's own exploratory values (1.4198 ... 1.7572, all six day intervals positive) are known-answer TARGETS for the audit comparison only; they are never typed into the repo and a mismatch beyond tolerance is reported, not tuned.
Falsifier: any restricted cell whose day interval includes zero or a negative point slope would be reported as is; the wording ladder ("positive in all six" vs "positive in k of six") is computed by the script from the cells, never fixed in advance.
Display: one sentence appended to `jointMatrixSentence()` bound to `S.resistanceJointSensitivity.supportRestricted` (count of cells with the day interval excluding zero, slope range, population counts, the selection caveat). Language gate rules added with the ledger id.
