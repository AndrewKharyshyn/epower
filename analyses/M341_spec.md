# M341 Regenerate the 37 RAW-class seasonal contracts on the live 489-drive corpus: pre-registered spec rev 2 (Director changes applied; work in progress)

Origin: HANDOFF step 7 ("regenerate stale seasonal contracts on 489"); M296 refreshed the 9 master-class charts and left 37 RAW-class entries in `seasonalCharts.charts` carried forward at the 410-drive basis (`seasonalCharts._staleness.stillStale`), disclosed but stale. Consequence: in the Warm, Shoulder and Compare views these charts show 410-drive data while the All view (top-level blocks) shows 489-drive data (checked on disk: SpeedDist overall shares 15.5/21.9/24.8/22.5/14.6/0.6 in the seasonal copy vs 16.1/23.0/25.0/21.5/13.8/0.6 in the top-level block). No new estimand: the same released estimators are run per thermal cohort on the live corpus.

## Method (pre-registered)
1. Tool `tools/regen_seasonal_raw.py` (new). Inputs: `drive_master.csv` joined to `seasonal_drive_master.csv` on `file` (cohort label `thermal_regime`; the join must be complete), the staged `raw_only/` raw view (basis `raw/`, F03 provenance-sensitive) and `drive_raw_cache.make_frame_loader()`. For each of the 23 core charts: `category_B(sub, loader, frame_loader)` once per cohort subset (warm, shoulder) and once on all rows. For each of the 14 builder charts: the builder on the same subsets.
2. PARITY GUARD (per chart, per builder call): f(all rows) must equal the fresh top-level block byte-for-byte (canonical JSON). A chart whose guard fails is NOT spliced: it stays carried forward, is listed with its reason, and the milestone reports the partial result (no tuning to force parity). Charts whose top-level block is itself carried forward (check `_artifactStamps` computationStatus) are carried forward in the seasonal copy too and listed.
3. Splice (additive, as M296): `seasonalCharts.charts[ID].data.{all,warm,shoulder}` = the fresh results, `data.cold` stays null (no observations, n=0), `basisNDrives` = live count, `refreshedBy` = this milestone; `coverage` entries (n_drives, km, independent days per cohort) are regenerated from the same subset definitions; `_staleness.stillStale` loses the refreshed ids and gains `refreshedRawCharts`; the stale-basis `reason` text is rewritten from the live lists (generated, not typed). `m295_payload.py` (stable class keys / not-observed strata) is re-applied afterwards; the shipped post-step must stay idempotent.
4. Cohorts: warm and shoulder only (cold: null with the existing `ColdNoData` path). Cohort sizes are read from the payload (`cohortMeta`); a cohort subset with fewer than the minimum support stays null by the existing rules, not forced.
5. Seed/RNG: builders that bootstrap use their own fixed seeds; the guard proves determinism on the all-rows call. No seed is changed in this milestone (the audit's "seed change" item is a separate decision, not bundled).
6. Not in scope: the master-class charts (done in M296), any top-level block, any estimator change, the Fuel-tab keys (fuelAnalytics, fuelStates, fuelWarmup), the Compare numeric-x parity item, article text.

## Rev 2 (Director verdict "revise": changes applied; these override the text above where they conflict)
- D1: the parity guard is necessary, not sufficient. It proves f(all rows) is the released, deterministic estimator; it does not prove f(cohort subset) is that estimator applied to a subset, because some builders derive cutpoints from the `dm` they receive (known: `_crawl_stop_go_two_part` tertiles via np.percentile(vpeaks,[33.3,66.7]); `engineStartContext` sample_n=12; `eolBaselines` socWindow). Required: the tool lists, per builder, every corpus-derived cutpoint it finds (static scan plus the builder's own outputs); each is either (a) held at its ALL-ROWS value for the cohort calls (a deviation from "pure subset", needs a Director ruling per builder; default: NOT done, no builder code is modified here) or (b) the chart is labelled cohort-relative in its coverage note. Default adopted: label cohort-relative; no estimator change. A partial splice (failing charts stay carried forward and are listed) is accepted.
- D2: the SAME `frame_loader` as the pipeline (`drive_raw_cache.make_frame_loader()`, schema v7) is used (7 builders return None without it); the tool states the cache schema version and why the cache has 490 entries for 489 drives (to be explained from the cache index, not assumed); builders that read `raw_dir` (`_vgt_airpath`, `_thermal_fuel_penalty`) get the same `raw_dir` (staged `raw_only/`) as the top-level build.
- Parity target = the COMPOSED top-level block: crawlStopGo + `_csg2` (two-part), highSocRegen + covariates, thermalFuelPenalty + continuous; the composition rule is copied from build_summary_arrays and verified by the all-rows guard.
- D3: audit scope raised: one chart per statistical class, shoulder cohort in at least two: pooled-share histogram (SpeedDist), pooled quantile (RpmDistribution or TorqueBySpeed), per-drive median with day bootstrap (a builder chart), min-N-gated curve (WarmupCurve or BatteryThermalCurve), event count/ratio (EngineStartsByType or CrawlStopGo). Plus a deterministic conservation gate over all 37 charts: every count-type leaf (nDrives, hours, nStops, seconds, km, event counts) satisfies warm + shoulder == all (cold is null/0); non-conserving leaves are listed with their definition (e.g. medians do not conserve and are excluded by type, not by hand).
- D4: `seasonalCharts._staleness` is replaced by ONE generated block from per-chart status (refreshed / carried forward with reason / parity failed), keeping the history keys; the wrong `refreshedMasterCharts.basisNDrives = 446` is fixed by this milestone.
- Master-class charts: the 9 master-class entries are at the 446 basis (M296): `m296_refresh_master_seasonal.py` is re-run at 489 FIRST (its own parity guard applies; step 0) and its result is part of this milestone's before/after table.
- Empty-bin semantics: zeros that arise from empty bins (`_pct` returning [0.0]*n; `engineOnBySpeed` 0 where total = 0) are shown as not-observed, not zero; per-bin n is emitted where the builder has it; the cohort minimum support (10 drives) does not cover bin support, so bin-level n is displayed. If a builder cannot emit per-bin n, the chart is listed as "bin support not available".
- `category_B` skips files silently on exceptions: the tool asserts files loaded == subset size (for every cohort call) and records the counts; a mismatch stops that chart.
- Before/after table covers the Compare views; jsx Conclusions texts and captions are grepped for warm/shoulder literals (any literal bound to a stale basis is bound to the payload or reported).
- Missing evidence to be produced by step 1: parity result for each of the 14 builders; measured run time; a check that the stored 410-basis contract shape equals the builder output shape.
- Limits to be stated in the CHANGELOG/notes: shoulder is confounded with calendar period (season-associated, not a temperature effect); basis raw/ (F03 provenance-sensitive), no article use; `cycleBySpeed` rates use CAP_KWH 2.1 (verified:false).
