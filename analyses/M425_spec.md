# M425 spec (Rev 0): bit-identical speed-ups inside the arrays build (speed-up 2 of the M422 profile)

Status: tooling milestone; no figure changes. Origin: the M422 cProfile and the wall-clock section profile `analyses/perf_profile_sections_2026-10-13.json` (arrays build 1,355 s on the 574-drive rehearsal state; the cost is spread over many builders: `_buffer_impulse_events` 137 s over 3,175 calls, `_engine_dwell_survival` 89 s (84 s of it the fixed-interval cross-check), `_cell_health_trend` 66 s, `_thermal_fuel_penalty` 64 s, `_csg_grid` 64 s, `_power_fade` 59 s, `_ramp_latency_events` 57 s, `_of_grid` 54 s, `_engine_start_triggers` 28 s over 4,495 calls). Owner order: exposureBasis, then speed-ups.

## Changes (each reproduces the former output exactly)
1. `_fixed_interval_self_transition(seq_all, window_s)`: the nested pandas form (`resample().apply(lambda x: x.mode().iloc[0] ...)`, 880 k Python calls) is replaced by sorted counts per window (windows anchored at the midnight of the first timestamp like `origin='start_day'`; modal state, ties to the smallest; empty or all-invalid windows dropped before the consecutive comparison). 84 s -> 0.5 s. Test `tests/synthetic/test_fixed_interval_self_transition.py`: the pre-M425 form (verbatim reference in the test) on 42 synthetic sequences (ties, invalid states, gaps, sub-second stamps, midnight crossing, all datetime units) and on all 553 real sequences, where it also reproduces the published `engineDwellSurvival.fixedIntervalSelfTransition`.
2. `_engine_start_scan(rpm, pre_off_s)`: the sustained-off -> running scan of `_buffer_impulse_events`, `_ramp_latency_events` and `_engine_start_triggers` (one boolean mask over the whole frame per candidate start) becomes a searchsorted slice when the time column is non-decreasing (the former mask form is kept as the fallback); `_buffer_impulse_events` uses slices for its three windows on the current series; `_ramp_latency_events` vectorises the stop search and the plateau run-lengths (the former form indexed the frame once per row). Test `tests/synthetic/test_start_event_scan.py` against the verbatim pre-M425 functions (`tests/synthetic/reference/compute_summary_arrays_pre_m425.py`) on 40 synthetic frames (sorted, unsorted, duplicated time stamps) and every 14th real frame; the full corpus (554 frames, three functions, no mismatch) is recorded in `analyses/M425_equivalence.json`. One pass over the corpus 43 s -> 27 s; the functions run about 5.7 times per drive in one arrays build.
