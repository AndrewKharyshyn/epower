# M513 spec (Rev 1): stamps built from declared dependencies, with an append-only lineage (audit 2026-10-25 A06)

Status: Rev 1, written 2026-10-25 BEFORE any M513 change to a stamp. Origin: independent audit 2026-10-25 A06 (8 computed stamps name an old raw-manifest corpus hash; several `fullConfigHash` values differ from the live config) and an Opus dependency analysis (2026-10-25). Both release-gate warnings (M300 config, M468 manifest) are existing open items; this milestone resolves their cause. No block content, figure, `drive_master.csv`, `raw_manifest.json` or raw file changes.

## Diagnosis (from the code, to be re-verified by the first tests)
The stale fields are a stamping defect, not stale data. `tools/restamp_blocks.py --regen` updates only `corpusHash`, `generatedAt` and the note, so `upstreamHashes` (backfilled at M294 from the 2026-09-25 manifest) and `fullConfigHash` (write-once at M284) survive. `tools/build_ambient_table.py` and `tools/record_spread_fit.py` deep-copy the `cohortMeta` stamp and inherit its fields. For raw-dependent blocks (`generatorTractionRecon`, `seasonalCharts`, `provenanceSensitivity`) the stamp therefore names a raw identity the content was not computed on; for the other blocks the raw-manifest field is not a dependency at all. `computedAt` in these stamps is the stamping-pass time, which must not stand in for the calculation time.

## Design
1. `tools/stamp_dependencies.json`: one entry per block that has a producer: `{producer, readsRaw, readsRawManifest, configSections[], inputFiles[]}`. Only the eight audited blocks are declared in M513; any other block keeps today's stamp (no behaviour change) and the gate treats an undeclared block as before.
2. `tools/stamp_common.py`: `make_stamp(block, deps, prior, milestone, note, computed_at)` builds the stamp from the declared dependencies only: `rawManifestCorpusHash`/`rawManifestSnapshotId` only if `readsRaw` or `readsRawManifest` (snapshotId is a label, never an identity); `configSectionHashes` = md5 of canonical JSON (sorted keys) of each declared `summary_config.json` section; `inputFileMd5` for declared input files; the master MD5. No cloning of another block's stamp.
3. Append-only `stampLineage` list inside the stamp: before any identity field (`corpusHash`, `upstreamHashes`, `fullConfigHash`, `generatedAt`) is overwritten, the prior identity `{corpusHash, upstreamHashes, fullConfigHash, generatedAt, milestone, reason}` is appended; existing lineage entries stay byte-identical.
4. `computedAt`: the block's own time (`spreadFitProvenance` latest `generatedAtUtc`; GTR per sub-block) or the ingest-run record of the producing stage; otherwise `null` plus `computedAtNote`. Never the stamping-pass time; never equal to `includedInReleaseAt` by default.
5. Producers changed to call `make_stamp`: `restamp_blocks.py` (`--regen`), `build_ambient_table.py`, `record_spread_fit.py`, `patch_m284_data.py` (the write-once guard is not loosened; it appends a lineage entry only when it writes), the arrays builder's per-block stamp path stays as is for undeclared blocks.
6. One-time backfill of the eight stamps, with a leaf diff showing that only `_artifactStamps` changed. Cheap producers (`ambientTable`, `cohortMeta`, `crossVehicle`, `provenanceSensitivity`, `spreadFitProvenance`, `assumptionsRegistry`) are re-run in a sandbox copy first and the block must be byte-identical before its stamp is re-derived (a differing block STOPs that block, nothing is forced). `generatorTractionRecon` and `seasonalCharts` are NOT re-run (a GTR re-run would trigger the M466 flip/acknowledgement route): their raw identity is ATTESTED from git history (`raw_manifest.json` `corpusHash` at the commits of the M463/M466 ingestions), written with `source: "attested at M513 from git history"`, never "recorded at computation". Where the attestation cannot be made from git, the field is left absent with a note and the block stays on the existing WARN.
7. `release_check.py`: after the backfill passes, (a) the M468 check becomes FAIL for blocks declared `readsRaw`/`readsRawManifest` whose `rawManifestCorpusHash` differs from the live one; (b) a FAIL for a declared block whose `configSectionHashes` do not match the live config sections; (c) the whole-file `fullConfigHash` check (M300) becomes INFO and the value moves into the lineage. A FAIL on a headline block (`generatorTractionRecon`, `seasonalCharts`) escalates to the Director. No promotion before the backfill is green.

## Must not
Blanket restamp (keeps the M468 ruling); copying the live raw-manifest hash onto a block whose dependency is undeclared or unverified; deleting or overwriting prior identities; setting `computedAt` to the stamping time; using `snapshotId` as an identity; changing any block content, figure, master or manifest; loosening the `patch_m284` write-once guard; promoting the gate before the backfill passes; re-running the GTR family. Language: "stamp metadata re-derived from declared dependencies", "prior identity kept in stampLineage"; never "corrected", "fixed provenance" or "verified" for a backfill.

## Tests and gates
Known-answer: mutating a declared config section changes its hash, mutating an undeclared one does not; lineage is append-only (prior entries byte-identical); a non-raw block carries no rawManifest field; `computedAt` is never later than `includedInReleaseAt` and never equal to it by default; negative control: a stale raw hash on a `readsRaw` block triggers FAIL; idempotence (a second run changes nothing). Chain: py_compile, JSON round trip, isolation diff (only `_artifactStamps` and nothing else), `release_check.py`, semantic gate, `stamp_basis.check`, CI unit list, jsdom. Blind audit (analytical-auditor) of the backfill: for each of the eight stamps, claim + data path only (the declared dependencies and the live files), reproduce the section hashes and the attested manifest hash from git. Director decision on the final stamps and on any headline-block FAIL.

## Out of scope
Any change to the other ~167 stamps; recomputing any block; the stamp of `generatorTractionRecon.crossval` (carried); new dependency declarations beyond the eight (follow-up).


## Rev 2 (research-director ruling "revise", R1-R9; this section replaces any conflicting Rev 1 text above; written before any M513 stamp change)
Meaning: metadata-only provenance fix, sound in intent, but as written the next `restamp_ingest` run would undo it (`stamp_basis.derive` resets `computedAt` to `generatedAt`; a lineage trigger on `generatedAt` appends an entry every run). Lineage does survive the arrays build for the eight blocks (`ingest_core.carry_forward` copies the whole prior stamp of blocks the build does not produce); `restamp_blocks --regen` re-applies them every ingestion and would put the live raw hash on GTR / seasonalCharts sub-blocks that were not recomputed.
R1: `stamp_basis.derive` / `check` honour declared blocks: they do not overwrite `computedAt` / `computedAtNote`. Known-answer: `restamp_ingest` run twice leaves the eight stamps unchanged.
R2: lineage appends only when an identity VALUE changes (`corpusHash`, raw hash, `configSectionHashes`, `inputFileMd5`, `fullConfigHash`), never on `generatedAt` alone. Lineage reason strings pass language_gate A2.
R3: schema compatibility: `corpusHash` = live master; `corpusHashSource` starts "file:" (build_html M235 gate); the raw hash lives under `upstreamHashes.rawManifestCorpusHash` (the M468 reader); `rawManifestError` is never written (semantic_gate D); the GTR `computationStatusNote` order is kept (restamp_blocks -> stamp_notes -> stamp_basis).
R4: the live raw hash is written on regen only from the producer's run record for THIS ingestion, never from the restamp pass itself; raw identity is kept per sub-block for GTR and seasonalCharts; `carriedBlocks` / `stillStale` keep their own identity or an absent one.
R5: a sandbox test of the next ingestion: carry_forward -> producers -> restamp_ingest -> stamp_basis with a touched master and raw_manifest; lineage persists, nothing is reverted, gate green. Test the `ingest_stages.json` order: config-editing stages (extend_session_ledgers, ambients) run before the producers of the declared sections.
R6: canonical section hash = md5 of `json.dumps(section, sort_keys=True, ensure_ascii=False, separators=(',', ':')).encode('utf-8')`; declare computational sections only; a wording edit to an undeclared section must not FAIL.
R7: attestation evidence per field: block blob identical from commit C to HEAD; `raw_manifest.json` corpusHash at C; CHANGELOG / run record showing the producer ran at C. If any part is missing the field stays absent (WARN). Git shows only which manifest was in the tree, not what the computation read; GTR.crossval and `seasonalCharts._staleness.stillStale` sub-blocks have no live raw identity.
R8: sequencing: backfill -> blind audit -> Director ruling -> gate promotion in a SEPARATE commit after a dry run with 0 FAIL. A headline block that would FAIL stays WARN under a recorded Director ruling.
R9: added gates: build_html stamp gate, language_gate A2, md5 of drive_master and raw_manifest before/after, CI unit list, headline CI gate (0 estimates moved). `ambientTable` and `spreadFitProvenance` are not in STAMP_POLICY and depend on producer order: STAMP_POLICY entries or an explicit order test.
