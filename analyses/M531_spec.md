# M531 spec (Rev 1, DRAFT for Director review): day-clustered interval for the motored share of the boost-classified engine hours (the "0.9 %" shown beside the RPM Distribution chart)

Status: PRE-REGISTERED DRAFT, 2026-10-28, written before any result exists. Owner: Andrii (chat, 2026-10-28: "continue" after M527; item "interval for the motored share", the last open follow-up of M523/M527). Origin: M523 bound the motored share to the payload hours (`motoredShareText`: "0.9 % of boost-classified engine-on hours (bins >= 1400 rpm; motored 0.75 h of 79.4 h; descriptive, no interval)"); the Director's M523/M527 rulings put the interval in a separate analysis because the payload holds only pooled hours per rpm bin, not per-drive hours.

## 1. Estimand

Motored share = motored seconds / (motored + fuelled seconds), pooled over the drives of the master that carry both the boost and the calculated-load PIDs (the boost-verified path of `compute_summary_arrays._RawAccum.add`, the same path that builds `rpmDistribution.motored` and `.fuelled`), over the engine rpm bins at or above `params.fuelStateRpmMin` (1400 rpm; bins with lower edge >= 1400, as displayed). Classification exactly as the pipeline (M84 / M46 / M48 thresholds, read from the module constants, not retyped): on the 1 Hz grid, base = eng_rpm > RPM_HIST_FUELSTATE_RPM_MIN; motored = base and boost < RPM_HIST_BOOST_MOTORED and eng_load_calc < RPM_HIST_LOAD_MAX; fuelled = base and boost >= RPM_HIST_BOOST_FUELLED; seconds weighted 1. The load-proxy path (drives without boost) never labels motored and is excluded by construction. This is an observed share of classified seconds of logged signals (boost is the app-calculated boost, load is the app-calculated engine load), not a measured fuel state and not an energy share.

## 2. Method

1. Per-drive sidecar `rpm_fuel_state_sidecar.csv` (tracked; keyed by the raw-file SHA-256, the source hash of the new grid function, and the threshold constants in a meta file; only new or changed drives are parsed): per drive, the motored and the fuelled second counts in each of the 13 `RPM_HIST_EDGES` bins, the boost-verified flag, and the number of classified seconds. The grid replicates `_RawAccum.add` for the three columns jointly (RAW_MAP rename, `_ft` time, `col()` ffill(limit=15) with the rpm >= 0 filter, `resample('1s').mean()`, `ffill(limit=15)`, `dropna(['eng_rpm','boost'])`); `grid_rpm` from `tools/rpm_opt_band.py` is not sufficient (it carries rpm only) and the new function is the only new grid code.
2. FAITHFULNESS GATE (STOP if it fails): per bin, the pooled motored and fuelled counts reproduce `rpmDistribution.motored.hours` and `.fuelled.hours` (round(count/3600, 3), max abs difference <= 0.002 h) and `nSamplesS`; the count of boost-verified drives equals `coverage.nDrivesFuelState`; the headline share equals sum(motored.hours[bins >= 1400]) / (sum(motored) + sum(fuelled)) of the stored payload (0.941 %).
3. Statistics: pooled ratio-of-sums; day-clustered percentile bootstrap (seed 42, `integers(0, D, (B, D))`, B = 4000, calendar day = cluster; ratio of sums inside every draw); n reported as drives and days (and days with at least one motored second). Because motored seconds are rare and zero-inflated across drives, also reported descriptively: the number and share of drives with at least one motored second, the per-drive share distribution (median, IQR over drives with >= 600 classified seconds), the share of the motored seconds contributed by the 5 largest drives, and a leave-one-day-out range of the pooled share. Sensitivities: cohort (warm / shoulder / cold, `seasonal_drive_master.csv` `thermal_regime`; the displayed share follows the shown cohort; a cohort with fewer than 5 days that contain motored seconds gets NO interval and is labelled exploratory), polling-regime period (slow-polled / fast-polled, `cadence_regime.csv`, confounded with date, season and ambient), and the exclusion of the canonical outliers (`ens_outlier_v2`).
4. Output: sibling payload key `motoredShare` (+ stamp; ingestion stage `rpm_fuel_state`; declared dependencies; tracked sidecar), written by `tools/rpm_fuel_state.py`; first output kept in `analyses/M531_result.json` (run-once lock; spec hashed before the first run).

## 3. Acceptance, falsification, escalation

- A1 faithfulness gate passes; known-answer tests on synthetic drives (hand-counted motored / fuelled seconds; boost exactly at -0.70 and -0.55; load exactly at 8.0; rpm exactly 1400.0 excluded (base is strict); a drive without boost -> not on the boost-verified path; NaN boost seconds dropped; duplicate timestamps; one-drive day; cache invalidation by threshold constants and grid source hash).
- A2 the pooled estimate equals the stored 0.941 % to rounding; the boost-verified drive count equals `coverage.nDrivesFuelState`.
- A3 blind `analytical-auditor` reproduces the pooled share, its interval and n from raw (claim + convention + raw path only, never the expected numbers).
- A4 escalate to the Director if the interval half-width exceeds the point estimate (the share is then not distinguishable from zero in relative terms), if the 5 largest drives contribute more than 50 % of the motored seconds, if the leave-one-day-out range exceeds the bootstrap interval, if any cohort other than cold has fewer than 5 days with motored seconds, or if the slow- and fast-polled shares differ by more than their combined intervals. Tripwires, not tests.
- Stop: faithfulness failure; any change to an existing payload value or key; the stage exceeding +120 s per ingestion (cached path expected about 10 s).

## 4. Display (after numbers, audit and Director; separate step)

`motoredShareText` shows the interval beside the share: "X.X % (95 % CI a-b, day-clustered; N drives with motored seconds of M, D days)" for the shown cohort, "exploratory, no interval" where the pre-registered rule says so; the "descriptive, no interval" label is dropped only where an interval is shown. Language: "observed share of classified seconds (app-calculated boost and engine load)", never "measured fuel state", "fuel cut" as a finding, "corrected", "robust"; the motored class is a rare, zero-inflated state and the text says so.
