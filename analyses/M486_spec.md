## Question
The headline resistance-proxy trend (powerFade, +0.656 mOhm/month, 274 drives on 98 days) is the primary estimand since M207/M481. The released equivalence test (locked bound, TOST) and the serial-dependence / dependence-sensitivity rows run on the S0 design (`resistanceVreg`: months + T + load current, +0.886, SE 0.537, equivalence not established), which differs from S1 by lacking the two HV-current-density covariates. The dashboard therefore says "no equivalence test exists for the primary design". The question: **is the primary design's slope equivalent to zero within the locked bound over this window, by the same TOST procedure as S0 and by the bootstrap procedure of the published interval?** A result of "not established" is not evidence of no degradation (short window); "established" would mean only "within the bound over this window". (Rev 2) **The verdict is determined by published values**: the published S1 point estimate (+0.656) already exceeds the locked bound (0.5439), so a 90 % interval centred on it cannot lie inside the bound and the outcome is "not established" under both procedures. This milestone formalises that and closes the disclosure gap ("no equivalence test exists for the primary design"); it is not expected to move any conclusion. The spec is NOT blind: it was written with the S1 slope and the bound known. The test is re-run at every ingestion without alpha spending (repeated looks are disclosed in the block); an interval is never compared with the bound at the 95 % level. A later change of the verdict at an ingestion is escalated to the Director, and the first "established" requires a blind audit before it may be displayed (the semantic gate fails on an "established" verdict whose `blindAuditRef` is empty).

## Population and designs (frozen)
- Outcome `vreg_R_pack_mohm`; canonical-clean drives (`ens_outlier_v2` false via the module's `_as_bool`), complete cases of the outcome, `T_pack_mean_avg`, `vreg_I_p95_A` and `date`. S1 additionally needs resolvable density (as `_powerfade_cadence_specs`: `have_d`, finite density and coverage); expected 274 drives on 98 days (equal to the S0 rows).
- **S1 (primary design, exactly the published one)**: OLS of the outcome on months, `T_pack_mean_avg`, `vreg_I_p95_A`, `eff_dt_s` (median positive inter-sample interval below 20 s of the HV-current channel) and `coverage_frac` (share of logger rows carrying a current sample), computed by `compute_drive_summary_v6._i_channel_sampling_density` from the raw file of each drive. The tool calls that function (not a reimplementation).
- **S0 (reproduction control)**: the released `resistanceVreg` design (months + T + `vreg_I_p95_A`), run through the same code path on the same rows; it must reproduce the released `degradationTrends.resistanceVreg.clusterRobustOLS` (slope 0.886, SE 0.537, 274 drives, 98 days) and the released TOST (pTOST 0.7372, 90 % interval [-0.0058, 1.7778]).
- Months origin and scale: `degradation_trends._prep` (days / 30.4375 from the earliest date), as S0. The published powerFade bootstrap uses days / 30.44; the slope differs in the fifth decimal and the reconciliation below uses a tolerance of 0.002.

## Procedures (frozen)
- **Bound**: the locked `oem75pct_over14yr` delta, read as a constant from `degradationTrends.resistanceVreg.releasedEquivalence.delta` (0.5439 mOhm/month, locked 2026-08-11); never recomputed from the current median, not rescaled for S1.
- **Primary (CR1 TOST)**: cluster-robust OLS (`degradation_trends._cluster_ols` with the density columns passed as extra covariates; day clusters; CR1 small-sample factor; t(G-1) reference), then `degradation_trends._tost(slope, se, delta, df=G-1)`: equivalence iff the 90 % interval lies inside (-delta, +delta) and both one-sided tests reject (alpha 0.05).
- **Secondary (bootstrap)**: the day-cluster percentile bootstrap of the S1 slope exactly as `_powerfade_cadence_specs.fit` (resample whole calendar days, 4,000 draws, seed 42, draws with fewer than 3 distinct months dropped), reported as the 90 % percentile interval (5th and 95th percentiles) and compared with (-delta, +delta). (Rev 2) The number of draws used and dropped is reported. Both procedures give 90 % intervals at alpha 0.05 per side; the "both must agree" rule is an intersection-union rule and therefore conservative.
- **Decision rule**: **established (within the bound over this window)** iff BOTH the CR1 TOST and the bootstrap 90 % interval place the slope inside the bound; **procedure-dependent, not established** iff exactly one does; **not established** iff neither does. No other classification; no sentence derived from the 95 % interval alone.

## Sidecar and stage (engineering, frozen)
`powerfade_density.csv` (TRACKED in git, like `ah_throughput.csv`; one row per master drive with a vreg proxy: file, date, eff_dt_s, coverage_frac, raw_sha256, method_version, reason), written only by `tools/powerfade_equivalence.py`, incremental by raw SHA-256 and METHOD_VERSION exactly as the M402 Ah sidecar (a drive is re-read only when its raw hash or the method version changed; the density is computed by the production function, so a drive whose density cannot be resolved has null values and drops out of S1). The tool then builds the block `powerFadeEquivalence` and splices only `/powerFadeEquivalence` and its stamp (coherent timestamps, `STAMP_POLICY` entry as regenerated). Stage `powerfade_equivalence` after `window_caveat`; it needs `raw/` like `ah_throughput`. `--check` (read-only, no raw needed) refits S0 and S1 from `drive_master.csv` and the tracked sidecar (CR1, TOST and the bootstrap, not only a comparison of JSON text) and verifies the block against the payload.
Hard stops (Rev 2; any failure makes the stage fail and write nothing): (i) the S0 control must equal the released `resistanceVreg` OLS and TOST (slope, SE, n, days, pTOST); (ii) the S1 CR1 slope must equal the published `powerFade.slopeMohmPerMoTctrl` within 0.002 and have the same n; (iii) the S1 bootstrap, before the 5th and 95th percentiles are taken, must reproduce the published `powerFade.ci95MohmPerMo` ([-0.426, 1.837]) and `nBoot` (4,000) from the same draws; (iv) the fitted S1 formula must contain BOTH density columns (`_covars_present` silently drops a covariate present on half of the rows or fewer, which would turn S1 into S0 without an error); (v) the S1 drive-file set must equal the set of clean complete-case drives, computed both with the released coercion (`fillna(False).astype(bool)`) and with `_as_bool`, and both must give the same file set, whose size equals `powerFade.nClean` (not just n); (vi) the published `powerFade.cadenceControlled` must be true (the 80 % engagement rule of the released function). The stage runs after the powerFade block has been recomputed on the final master, so (ii) and (iii) do not compare with a stale value. The raw directory is resolved with the `XT_RAW_DIR` default exactly as `tools/ah_throughput.py` does.
