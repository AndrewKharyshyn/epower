# M664 spec (Rev 1): UI-05 eighth slice, fuel-data coverage by month

Presentation only, written before the build. The Fuel-tab banner "What the fuel data are, and how much of the record has them" prints per month the file count, the files with fuel columns and the files with a usable rate and counter, only as a table. M664 adds a point chart of the two shares (withFuelColumns / files and usableBoth / files) per month, bound to S.fuelContract.coverage.byMonth; the points are shares of file counts, so no interval is drawn or invented. The month table stays behind ChartWithTable unchanged. Backlog item "coverage heatmap by PID/month" is reduced to this existing per-month block: no per-PID by month key exists in the payload and none is created here. Also decided in this slice: the backlog item "tornado for methods shifts" is NOT implemented: the M514 joint matrix (54 cells) exists only as a sentence, so a chart would be a new display, not a table conversion (it needs its own spec and Director review), and the provenance-sensitivity metrics are in different units, so a common axis would mislead. No payload, method or figure change. Test: test_fuelcoverage_chart.js (7 months x 2 shares equal the payload counts at 2 dp, open points only, table behind the toggle).
