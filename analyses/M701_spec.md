# M701 spec (Rev 0, pre-registered): demand-aware engine-start hazard (backlog N-10, first part)

Status: DRAFT for Director review; written 2026-11-16 before any estimator exists or runs. Payload only (additive key, no display, no article figure). Road-data items (CoC / WLTP, Cd x A, mass, coast-down) stay closed and are not used.

## 1. Question and non-claims
How does the instantaneous probability that the engine starts during an engine-off spell depend on the driver-demand signals (accelerator pedal position, target motor torque), on pack SoC and on speed, once the dependence among the drives of one calendar day is respected? The study tests the OEM start-logic statement (Nissan Technical Review No. 89/90: start is governed by required power and SoC) as a consistency check on logged channels. Non-claims: the hazard is a statistical description of logged channels, not the VCM calibration, not a causal effect of the pedal, not a threshold of the control law; "engine starts" are detected starts (existing detector: rpm > 300 for >= 2 s on the 1 s grid), not commanded starts.

## 2. Data and eligibility (fixed before any result)
- Unit of analysis: engine-off spell (rpm <= 300) inside a canonical-clean drive (`ens_outlier_v2 == False`), on the 1 s grid of the existing detector (`engineStartRate.detector`, M-numbers unchanged); a spell ends at an engine start (event) or at drive end / key-off (censored).
- Demand channels: accelerator pedal D (`Положення педалі акселератора D (%)`), target motor torque (`[VCM] Target Motor Torque`). Coverage varies by file (a May file carries target torque and no pedal; an August file both; some files neither): a drive enters the demand model only when the channel has > 90 % non-missing samples inside engine-off spells; per-drive coverage is stored. Pedal E is a redundancy channel used only for a D/E agreement check (flag, not repair).
- Support (existing ladder): a model/cell is shown only with >= 10 drives and >= 5 days; below it the block says "not estimable" with the counts. Feasibility counts (eligibility only, taken from the master and the per-file column inventory before any estimate) are written to the study file and recorded in the CHANGELOG.
- Lagged covariates: pedal and target torque enter as the maximum over the preceding 2 s (primary), with 0 s and 5 s lags as sensitivities; speed and SoC at spell time; pack temperature class (cold / shoulder / warm as in the seasonal block). All covariates use only samples up to and including time t (no look-ahead past the event second).

## 3. Method
- Discrete-time hazard on the 1 s grid, complementary log-log link (event within the second given off at the start of it); person-period rows thinned to every 2nd second for the fit (carried as a sensitivity: every second).
- Primary model M1: cloglog(h) = f(SoC) + g(speed) + h(pedal2s_max) with natural cubic splines (df fixed in advance: 4, 4, 4) and a cold / shoulder / warm class term.
- Reference M0 (no demand): the same without h(pedal). Demand value = day-blocked cross-validated log-likelihood difference M1 - M0 (5 folds of whole days, stratified by month), with a day-clustered percentile bootstrap interval (seed 42, 4000 draws); also the AUC of the per-second event prediction on held-out days. Target torque model M2 replaces pedal by target torque; M3 includes both (collinearity reported through the correlation and the VIF).
- Inference for coefficients: day-cluster sandwich (clustered by calendar day); coefficient intervals are shown only where both the sandwich and the day-bootstrap intervals exclude zero for the same sign; disagreement is reported, not tuned.
- Event definition sensitivity: rpm threshold 300 (primary) vs 400; minimum run 2 s vs 5 s; drive-start engine starts (first 60 s after key-on) excluded vs included (primary excludes them: warm-up starts follow a different logic).
- Calibration: reliability by decile of predicted hazard on held-out days; Brier score; a known-answer simulation (synthetic spells with a planted pedal effect, a planted day random effect and a null) checks that the day-cluster inference holds its size (false-positive rate for the pedal coefficient <= 0.10 at 200 replicates) and recovers a planted effect (power reported).

## 4. Primary vs sensitivity
Primary: M1 vs M0 on pedal-eligible drives. Sensitivities: lag 0 s / 5 s; M2 (target torque) and M3; every-second fit; event-definition variants; cadence stratum (fast / slow polled, B6 check failed and shown, no pooled contrast across strata; strata reported separately where support allows); cold class shown exploratory with no verdict wording below 10 effective days.

## 5. Accept / reject / falsify
- Supported (consistency with the OEM statement, wording ladder): the cross-validated gain of M1 over M0 has a day-clustered interval excluding zero AND the pedal term has the expected sign (higher demand, higher hazard) in the sandwich and bootstrap intervals AND the held-out AUC gain is positive with its interval excluding zero.
- Not established: any of these fails; with fewer than 10 pedal-eligible drives on 5 days the result is "not estimable".
- Falsifiers: demand adds nothing beyond SoC and speed (gain interval includes zero); the pedal effect has the opposite sign; the effect disappears when drive-start starts are included (then the result is a warm-up artefact).
- The known-answer simulation failing its size or power criteria blocks any result wording.

## 6. Outputs, tests, language
Additive key `engineStartHazard` (study file `analyses/M701_study.json` with the design fingerprint: n spells, n drives, n days, covariate coverage per epoch; staleness detected as in M680; stamp via `carry_declared`, isolation-guarded splice, no existing leaf changed; stage `engine_start_hazard` `verified:false`). Known-answer test `tests/synthetic/test_m701_start_hazard.py` (planted pedal effect recovered, null stays null, day random effect widens the interval, lag uses no future samples) in the CI python list. Language rule `M701-start-hazard-wording`: 'logged-channel hazard of detected engine starts, estimated'; never 'the VCM threshold', 'commanded start', 'the pedal causes', 'measured start logic', 'validated the OEM logic'; a supported result reads 'consistent with the OEM statement that start depends on demand and SoC'. No dashboard display in this milestone.

## 7. Risks and open points for the Director
R1 pedal is available only on a subset of files (epoch effect): season, firmware (battery software update, owner), cadence and the pedal channel's presence are confounded; the model is stratified by the eligible-drive set and says so. R2 spells are not independent within a drive (the hazard resets after each stop): the day cluster is a coarser, conservative unit. R3 pedal and target torque are near-collinear with speed change; M3 may be unidentifiable (reported, not forced). R4 the 2 s maximum lag is a design choice; 0 s and 5 s are sensitivities. R5 spline df and the 2nd-second thinning are fixed here, not tuned. R6 the start detector is rpm-based; a commanded start precedes the detected one by an unlogged lag. Questions: (1) is excluding the first 60 s after key-on right; (2) is the day-blocked cross-validated likelihood the right primary quantity rather than a coefficient; (3) the size criterion (<= 0.10 at 200 replicates): adequate or tighter; (4) is pedal-only primary with torque a sensitivity right given the coverage difference.

## 8. Rev 1 (2026-11-16, Director review "revise"; overrides conflicting text above)
1. Baseline duration: every model carries a natural cubic spline of time-since-spell-start (df 4, pre-set); M0 and M1 differ only in the demand term.
2. No look-ahead: covariates at second t use samples up to t-1 (the event is inside second t). The grid fill is last-observation-carried-forward only (the existing 15 s limit; no nearest or interpolation). The age of the carried pedal / torque sample is stored per row; sensitivity excludes rows with age > 5 s.
3. `nanIsOff=true` seconds are not at-risk time: they are dropped from the risk sets and counted per drive and in total.
4. Thinning is replaced by aggregation to 2 s intervals (cloglog with a log-width offset), so no events are dropped; the every-second fit stays a sensitivity.
5. Sign condition: a scalar, the log hazard ratio of pedal (2 s maximum) at its day-weighted 75th versus 25th percentile at fixed SoC, speed and duration, plus a monotonicity check of the fitted pedal curve over the P10-P90 range. "Expected sign" means this scalar is positive with the sandwich and day-bootstrap intervals excluding zero.
6. Falsifier corrected: an artefact is an effect present only WITH drive-start onsets. The 60 s exclusion removes onsets and at-risk time together; added sensitivity: exclusion by coolant below 60 C (engineStartContext coolCold) instead of the first 60 s.
7. Epoch: a feasibility table (pedal / torque coverage by month, cadence stratum, before / after the battery software update; counts of drives and days) is written before any fit. M0 and M1 are fitted on identical rows; M1 versus M2 only on the intersection set; torque never replaces pedal as primary after the fact; if pedal is not estimable the block says so and torque stays a sensitivity.
8. CV-gain bootstrap: held-out per-day log-likelihood contributions (folds fixed, seed 42; models refitted per fold once, not per draw) are resampled by calendar day, 4000 draws, percentile interval.
9. Naming: "RPM onset (> 300 rpm, run >= 2 s)" per `engineOnRule` separate names, not "engine start"; 400 rpm is a sensitivity (the engine-on rule uses > 400).
10. Reverse mask: seconds in M695 reverse-consistent episodes are excluded from at-risk time (target torque sign is ambiguous there); included as a sensitivity.
11. Relation to existing blocks: M701 complements `engineStartContext` (threshold labels), `engineStartRate` and `engineDwellSurvival` and replaces nothing; target torque is a VCM output (possible reverse causality), stated in the block.
12. Known-answer simulation (Director Q3): >= 500 replicates; pedal-coefficient size <= 0.075 at nominal 0.05; 95 % interval coverage >= 0.90; power reported at a planted hazard ratio of 1.5 per IQR at the real day count; the simulation includes within-drive dependence and a planted epoch confound. A failure blocks any result wording.
Answers to the Director questions: (1) yes, the exclusion applies to risk time too; (2) cross-validated per-day log-likelihood gain is primary, AUC secondary and not a gate; (3) tightened as in item 12; (4) pedal-only primary with torque as sensitivity, pre-registered with the feasibility rule.
Risks recorded: few pedal-eligible days (likely "not estimable"); epoch, cadence and firmware confounding not separable; slow-polled pedal staleness; target torque reverse causality.
13. Errata (implementation choices recorded before any fit): (a) the "day-bootstrap" for coefficient and hazard-ratio intervals is the day-cluster SCORE bootstrap (Rademacher day weights on per-day score contributions, one Newton step from the fitted coefficients; 4000 draws, seed 42), not a refit per draw (4000 refits of a model with about 10^5 to 10^6 rows is infeasible); the cluster sandwich and the score bootstrap must both exclude zero. (b) The AUC gain (secondary, not a gate) uses a day-resampling bootstrap with 300 draws. (c) Simulation gating: the size, coverage and power criteria of item 12 apply to the null design and the planted-effect design (day and drive random effects, within-drive dependence); the planted epoch-confound design (month-level baseline shifts correlated with the pedal mean, not adjusted by the model) is reported as a diagnostic and, if its false-positive rate exceeds 0.075, the block carries an "epoch-confounded" caveat and no supported wording. (d) The reverse-episode mask uses the cached M698 episodes with grid second k taken as seconds from the first timestamp (alignment error at most 1 s, disclosed). (e) A spell ends at the first on-sample; runs shorter than 2 s are not onsets and end the at-risk state; the first spell of a drive starts at key-on. (f) Covariates are winsorised once at the 1st and 99th percentile of the primary at-risk rows (outcome-independent), before any fit.
14. Errata (found by a pilot on 70 drives, before any full run; the pilot's numbers are not used): the spline terms use patsy `cr(x, df=4, constraints='center')` so that the design matrix has full rank (an uncentred `cr` term sums to one and is collinear with the intercept; the first version gave a rank-deficient matrix and undefined cluster intervals in some simulation replicates). The simulation reports the share of replicates with an undefined interval and a criterion fails if that share exceeds 0.02; an undefined interval is never counted as "not excluded".
