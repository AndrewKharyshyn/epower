## Scope

The strict `<` is kept (fast iff period < THRESHOLD_S).
2. Migrate the six consumers (seven code sites). Each inline cut is first CHECKED to be the logger-regime rule and not another cut, and each keeps its OWN missing-value behaviour exactly unless a second change is declared with its own difference set (R2): `m573_cell_spread_step.py:112,199` evaluate `period >= cut`, so a missing period counts as fast (`slow` = 0 / False) there; `timing_support.py:254` labels a missing period `unknown`; `dependence_sensitivity.py:204` and `m480_spread_sensitivity.py:59` map a missing period to `None`; `slow_flag` therefore takes a `missing` argument (`0.0` for the m573 behaviour) and the migrated code reproduces each consumer's old output exactly for missing values (script-checked on the 7 drives without a period).
   - `capacity_basis` (R3): the SIDECAR regime (`I_sample_period_s` through `cadence_regime.csv`, joined by drive id) is the rule of record; the per-drive median of the logged HV-current intervals (`np.median(np.diff(tI))`) stays a DIAGNOSTIC.
