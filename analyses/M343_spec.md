# M343 Engine-start rate from the RPM-onset detector (audit F10.r1 detector replacement, D-13): pre-registered spec rev 1 (work in progress: Director review pending)

Origin: audit v3 F10 ("StartsPer100km is based on battery-current sign crossings, not engine starts ... replace its builder with a supported engine-start detector. Separate cold thermal starts, ordinary RPM restarts and fuel-on starts; show counts, denominator and detector parameters") and ledger D-13/F10.r1 ("detector replacement in M327"). The wording half is merged (M329: "current-direction reversals per 100 km"). This milestone adds the supported engine-start quantity. New estimand (pooled engine-start rate) => spec, blind audit, Director decision. No article figure.

## Facts on disk (read-only)
- `StartsPer100km` (top-level KPI via refresh_seasonal_kpis.py, seasonal contract `StartsPer100km`): value 918.58 "starts/100km" from `n_sign_crossings` (battery-current sign reversals), nPool 446 (stale basis); the contract already says `supersededBy: EngineStartsByType` and that the proxy is "not promoted". It is a different physical quantity from engine starts and stays as the labelled reversal-density proxy.
- The released RPM-onset detector lives in `_RawAccum.add` (compute_summary_arrays.py ~4138-4162): 1 Hz grid `hz = g1.resample('1s').mean().ffill(limit=15)` built from the slim frame; `on = nan_to_num(eng_rpm) > 300` (NaN = off, so segments break at logger gaps); run-length encoding; only runs of >= `MIN_ENGINE_START_S` = 2 s count as starts; per drive `starts / distance_km * 100` is appended per time-weighted drive class (`CLASS_ORDER`). `engineStartsByType` publishes per-class lo/hi/MEAN OF PER-DRIVE RATES (an average of ratios; not a fleet rate).
- No per-drive start count is stored in `drive_master.csv` or the payload (only the per-class lists inside the accumulator), so a pooled ratio-of-sums with day clusters needs a new per-drive pass over the cached frames (`drive_raw_cache.make_frame_loader()`, schema 7).

## Estimand and method (pre-registered)
1. Tool `tools/engine_start_rate.py` (new): per canonical-clean drive (`ens_outlier_v2`/`ens_invalid` not True, `distance_km` > 0.5; M340 shared mask) from the staged frame cache (basis `raw/`, F03 provenance-sensitive): reproduce the released detector VERBATIM (same 1 Hz grid, rpm > 300, NaN = off, runs >= 2 s) and record per drive: n_starts, km, first-start flag (the first qualifying run of the trip = "trip-first start"), later runs = "restarts within the trip", the engine-coolant temperature at each start (the same `RE.CH` coolant channel as M337, latest valid sample within 120 s at or before the start, else unknown) and the time since the previous engine-off began (dwell, s). Detector parameters (threshold 300 rpm, 2 s minimum, ffill limit 15 s, grid 1 s) are written into the payload.
2. Estimates (ratio of sums only; day = trip start date; day-clustered percentile bootstrap, seed 42, 4000 draws; n drives and days on every estimate; interval only with >= 7 days, 5-6 low-cluster, < 5 points only):
   - pooled engine-start rate = 100 x sum(starts)/sum(km), for All, Warm, Shoulder (Cold: n = 0 / below support, shown as such), and by time-weighted drive class (urban, mixed, mixed_highway, highway; unknown excluded as in the chart);
   - decomposition per 100 km: trip-first starts and restarts within the trip (sum to the total by construction, asserted per drive);
   - thermal separation: starts by engine-coolant band at the start sample (< 40 C, 40-60 C, >= 60 C, unknown), reported as counts, share of starts and rate per 100 km, with the unknown share visible. These are descriptive associations of start context, not "cold-start" or fuel claims; fuel-on starts are NOT separated here (the logged fuel rate is not available for the older drives; the fuel subset is out of scope for v1).
3. Controls (before any splice): (a) known-answer: the per-class MEAN of per-drive rates computed by the new tool must equal the published `engineStartsByType` avg/lo/hi (rounded) on the same drive set; if it does not, STOP (the detector is not the released one); (b) all-rows total starts and km are reported next to `engineStartContext` / `socHysteresisV2` start counts, which use different detectors (>=2 s confirmed run vs single-sample >800 rpm trigger): the differences are listed, not reconciled (stated in the payload).
4. Payload (additive): new top-level key `engineStartRate` (script-written, stamped), plus a seasonal contract `EngineStartRate` (kpi-shaped like `StartsPer100km`: value, unit, estimator, nEligible, nPool, provenance, ci95; data.all/warm/shoulder; coverage; status; cold unavailable) so Compare shows it beside the proxy; `StartsPer100km` itself is NOT changed (kept as the labelled current-direction reversal proxy; its value is not compared with the new rate in text).
5. Dashboard: a new component in the Engine Cycling section (and in the Compare group `["StartsPer100km", "EngineStartsByType", ...]` the new `EngineStartRate` is added next to the proxy) with: the pooled rate and CI per cohort, the trip-first/restart split, the coolant-band table (counts, share, rate, unknown share), the detector parameters and the denominators (n drives, days, km), and an explicit sentence that engine starts (RPM onsets) and current-direction reversals are different quantities. All numbers bind to `S.engineStartRate`.
6. Language gate: forbidden "cold start" for a start with coolant < 40 C unless the table says "start with coolant < 40 C" (descriptive; no thermal-penalty or fuel claim); forbidden "engine starts" for the sign-crossing proxy (the W4 rule exists); required: detector parameters, n (drives, days), "RPM onsets are not current reversals", F03 label, not M299-reproducible.

## Verification plan
- Step 1 (control): run the tool in check mode, report the known-answer comparison with `engineStartsByType` per class, totals, runtime.
- Step 2: blind audit (analytical-auditor; claim + data path only; definitions: rpm > 300 at 1 Hz with NaN = off, runs >= 2 s, trip-first vs restart, canonical-clean, day-clustered CI): reproduce the All pooled rate and CI, the Shoulder pooled rate, the first/restart split and one coolant-band count. Director decision before the dashboard build.
- Step 3: splice (allow-list: `engineStartRate`, `seasonalCharts.charts.EngineStartRate`, their stamps, `_meta` counts if any; every other leaf byte-identical, deep-diff asserted); dashboard rebuild; gates (build, jsdom incl. cold-fixture/Compare, semantic, language, release_check); CHANGELOG; SendUserFile; PR.
- Stop conditions: known-answer mismatch; any cohort below support rendered as zero; the first/restart decomposition not summing; a leaf outside the allow-list changing.

## Decisions requested of the Director
D1 Additive (new `EngineStartRate`, proxy unchanged) versus replacing the proxy's content under the key `StartsPer100km`: proposed additive, because the contract already marks the proxy as superseded and the title/units were renamed in M329. D2 Is "trip-first start vs restart within the trip" plus "engine-coolant band at the start sample" an acceptable reading of "separate cold thermal starts, ordinary RPM restarts", given that fuel-on starts cannot be separated on the full corpus? D3 Should the pooled ratio-of-sums rate also be shown beside the published mean-of-per-drive-rates (`engineStartsByType`) with a sentence explaining why they differ, or only the new rate? D4 Any additional stop or required wording.
