## What the inventory found (facts, to be reproduced by the tool, not typed)
- `thermalWarmupLag` (coolant and oil time to 60/70/80 C): drives that never reach a threshold are removed (`mi()` drops NaN) and no count is stored, so the reported medians are medians of the reachers only (biased low); warm starts (coolant >= 60 C at the first valid sample) and drives with fewer than 30 valid coolant seconds are not counted; the oil start is NOT gated (an oil start at or above the threshold is recorded as time 0).
- `warmupCurve` (distance-domain coolant rise): warm starts (first valid coolant > 50 C), drives of a class outside CLASS_ORDER and drives with fewer than 3 valid coolant samples are dropped silently; per-point n is reported.
- `hvcEngine80C`: strings only ("51% of drives (n=467)"); the reached / not-reached counts are not separate numbers; no cold-start gate (warm restarts count as reached at about 0 min).
- `thermalFuelPenalty`: conditions on the coolant reaching 70 C (selection on the outcome); cold starts that never reach 70 C and drives rejected by the fuel gate are not counted.
- `thermalStepResponse` (138 candidates, 9 fits) and `fuelWarmup` already carry rejected-by-reason ledgers; `shortTripWarmup` reports crossed / n.
- Different "cold" definitions are in use (coolant start <= 50 C, none, < 60 C), so the counts of the estimators are not mutually reconcilable unless each ledger states its own definition.
- The cold cohort (7 drives, 3 days) is suppressed below the minimum support (10); intake air is valid for 270 of 554 drives, with no valid value after 2026-08-24.

## Definitions (fixed here, not tuned)
Population: all rows of `drive_master.csv` (the estimators do not filter on `ens_outlier_v2`; the ledger follows each estimator's own population and states it). Frames: the slim frame cache as the arrays build uses it (`drive_raw_cache`, `frame_loader`), raw files from the staged view (`raw_only`), the helpers and constants imported from `compute_summary_arrays` (`_twl_grid`, `_twl_time_to`, `_TWL_*`, `WARMUP_*`, `WARM_ENGINE_C`, `_apply_speed_priority`, `RAW_MAP`, `_of_grid`, `_OF_*`, `_cond_class`, `CLASS_ORDER`), so the ledger classifies each drive with the estimator's own rules.
For every estimator the ledger records, as numbers: `candidates` (definition stated), `excluded` (list of {reason, n}, mutually exclusive, applied in the estimator's own order), `accepted` (must equal the estimator's published n: a RECONCILIATION check, written into the block and into the semantic gate), `reached` / `censored` where the estimator is a time-to-threshold statistic, and the rule text.
- **warmupLag** (fluids coolant and oil; thresholds 60, 70, 80 C): candidates = rows with a frame; excluded = no frame or no coolant channel; fewer than 30 valid coolant seconds; warm start (first valid coolant >= 60 C). Cold starts: for each fluid and threshold: `reached` (finite time; oil: split into `atOrAboveAtStart` (time 0 recorded) and `reachedAfterStart`), `censored` (never reached within the observed span). Observation span of a drive = seconds from the first to the last second of its 1 Hz grid; `censoredObservedSeconds` {p25, median, p75, max} of the censored drives. **Risk-set counts** (counts, not a survival function): at times t in {60, 120, 300, 600, 900, 1800} s: `atRisk` (cold-start drives with min(time-to-threshold or span) >= t), `eventsUpTo` (reached with time <= t), `censoredBefore` (span < t and never reached). Oil: drives without >= 30 valid oil seconds are excluded (`noOilChannel`). The pooled medians of the estimator are medians of the reachers: the block states `medianIsOverReachersOnly: true` and the share reached.
- **hvcEngine80C** (classes urban, mixed, mixed_highway, highway): candidates = rows with distance_km > 0 and a frame with a coolant column; excluded = no valid coolant sample; class outside CLASS_ORDER; accepted per class with `reached` / `notReached`, `startedAtOrAbove80` (first valid coolant >= 80 C: warm restart counted as reached at about 0 min), `coldStartAndReached` (first valid coolant < 50 C and later >= 80 C), `coldStartNotReached`. 
- **warmupCurve**: candidates = rows with a frame, a coolant and a speed column; excluded = class outside CLASS_ORDER; no valid coolant; warm start (first valid coolant > 50 C); fewer than 3 valid coolant samples after the anchor; accepted per class (equal to `warmupCurve.classes[*].nDrives`); `gridAttrition`: n at each grid distance for the class with the most drives.
- **fuelPenalty** (Aug-12 fuel-accumulator subset): candidates = rows with a readable raw grid with the fuel accumulator and a speed channel (`_of_grid` not None); excluded = fewer than 60 valid coolant seconds; warm start (first valid coolant >= 60 C); cold start that never reached 70 C (`censoredNeverReached70`); cold start reached 70 C but fewer than 30 fuel-accumulator samples or no fuel increase > 0.02 L (`rejectedFuelGate`); accepted = published `nColdStartDrives`.
- **copied through, with their own n**: `thermalStepResponse` (candidates, fits, gateRejections), `shortTripWarmup` (n, nCrossed80), `cohortMeta.cold` (observed 7, 3 days, suppressed below minimum support 10, inference unavailable), `meta.intakeAir` (valid 270 of 554, last valid 2026-08-24, after-last-valid 276 drives on 45 days).

## Reporting rules (pre-registered)
1. The block is additive (`thermalSupportLedger` + stamp, spliced like `dependenceSensitivity`); no existing leaf changes.
2. Reading sentences are generated from the leaves: "n accepted of N candidates; k censored (never reached the threshold within the observed drive); w warm starts excluded; the pooled median is over the reachers only".
3. Winter stays suppressed: the ledger never produces a winter or cold-cohort estimate; it reports the suppressed counts only.
4. No survival model, no Kaplan-Meier curve, no extrapolation beyond the observed span; the risk-set table is a count table. A right-censored drive is not "a drive that failed to warm up": its observation ended (key-off) before the threshold.
5. Language: forbidden "detected/confirmed/robust/significant", "survival" estimates, "failed to warm up" for censored drives; required: "censored (observation ended before the threshold)", "reachers only".

## Known-answer tests (`tests/synthetic/test_thermal_support_ledger.py`, in CI)
Synthetic frames (cold start reaching 80 C, cold start ending at 55 C, warm start at 75 C, a 20-second file, an oil-warm start, a fuel-gate failure) classified by the same code path give hand-computed counts and risk-set tables; reconciliation: on the real corpus every `accepted` equals the published estimator n (coolant 315/234/165 reached of 370 cold starts; oil per threshold; `warmupCurve` per class; hvc n; fuel 121); mutation: a changed gate (warm threshold 50 -> 55) makes the reconciliation fail.

## Acceptance
Tool + tests green; reconciliation equal for every estimator on the live corpus; blind audit (analytical-auditor, definitions + raw path only) of the warm-start, censored and risk-set counts for the coolant 80 C and oil 70 C rows; Director decision on the wording before any dashboard text; dashboard binding (Thermal tab support lines bound to the ledger) per the dashboard change rule; `release_check.py` and CI green; CHANGELOG `M418`.

## Limits (disclosed in advance)
Single vehicle, one driver, May-October (ambient 3-38 C); cold start definitions differ between the estimators on purpose (each ledger states its own); censoring by key-off is not independent of the driver's trip choices (informative censoring is possible and not modelled); the ledger cannot recover winter support that does not exist; the estimators' medians stay as published and are labelled as reachers-only.

## Rev 1 (2026-10-12, before the dashboard text): cohort variants and binding
- **Reason.** The four thermal sections switch with the warm / shoulder cohort selector (`cohortOr(...)` over `seasonalCharts.charts.*.data[cohort]`), so one all-corpus support line would be wrong in those modes. The ledger therefore carries `byCohort.{warm,shoulder}`: the per-drive records are classified once and aggregated for the drives of each `thermal_regime` (`seasonal_drive_master.csv`, as `tools/regen_seasonal_raw.py` does); the cold cohort (below the minimum support of 10) is not computed (`cohortNote`, `coldCohort`).
- **Reconciliation extended.** Every accepted count is compared with the published estimator n of the same cohort: `ThermalWarmupLag.data[c]` (nColdStart, nDrivesTotal, nWithOil, coolant / oil n per threshold), `HvcEngine80C.data[c][class]` (n and the percentage in the string), `WarmupCurve.data[c].classes[k].nDrives`, `ThermalFuelPenalty.data[c].nColdStartDrives`; 66 checks (all, warm, shoulder); the semantic gate repeats them and a mutated count must fail (test).
- **Binding.** One component renders a support line under each of the four sections, text generated from the ledger leaves of the selected cohort (all / warm / shoulder; nothing in compare mode or for the cold cohort, whose placeholder already states the suppression). Wording is fixed by the Director review (`analyses/M418_director_ruling_2026-10-12.md`); sentences carry no new estimate, only counts, shares reached and the reading rule; `reachers only` is stated wherever a pooled time-to-threshold median is displayed.
- **Wiring.** Stage `thermal_support_ledger` after `serial_dependence` (needs `seasonal_drive_master.csv` and the seasonal chart payloads of the same ingestion); CI line for `test_thermal_support_ledger.py`; `semantic_gate` checks (reconciliation allEqual, rendered support lines equal the payload counts, forbidden wording absent); language-gate rules for the old wordings the Director lists.
