## 1. Facts
- Standing rule (CLAUDE.md): the canonical exclusion is `ens_outlier_v2` (== `ens_invalid`); energy rates use canonical-clean eligibility. The GTR family departs from it: the headline (`wire_gtr_seasonal.aggregate`) defines "clean" as `f_gen` not NaN (260 of 261 `fuel_recon_master` rows, 50 days, 2003.9 km), `speedSplit` uses all 261 rows, `gtrClosure` (M372) uses 257 (canonical-clean minus two NaN-offset drives).
- The canonical rule removes exactly two `fuel_recon_master` rows: `20260513_182950` (urban, 2026-05-13, 20.7 km, shoulder, f_gen NaN) and `20260813_144601` (urban, 2026-08-13, 0.9 km, warm, f_gen present). Canonical-clean set: 259 rows, all with f_gen, 50 days, 2003.0 km.
- Measured effect on the aggregation (`analyses/M375_eligibility_effect.json`, 49 compared fields in All): ONLY `nProduction` 261 -> 259, `nDrives` 260 -> 259, `kmProduction` 2003.9 -> 2003.0 and the urban drive-type split (n 242 -> 241, km 1256.4 -> 1255.5, f_gen 0.3722 -> 0.3719, genToTraction 7.16 -> 7.15, tractionGross 19.25 -> 19.24); every `corpus` field (generator, tractionGross, fGen, fuelL, fuelChem, etaEng, etaBus) is identical at published precision. Warm: 12 fields move by <= 0.01 (fuelChem 47.64 -> 47.63, the urban split, counts). Shoulder: only `nProduction` 81 -> 80. This is a DEFINITIONAL alignment with a negligible numeric effect.

## 2. Proposal
P1 `wire_gtr_seasonal.aggregate`: clean = `f_gen` notna AND `ens_outlier_v2 == False` (the merged frame carries the flag from `drive_master.csv`); `nProduction` counts the canonical-clean fuel-instrumented rows. `refresh_gtr_headline.py` then regenerates the headline (`nProduction, nDrives, kmProduction, corpus, flows, driveTypeSplit, productionCheck, basis`), the glossary f_gen values (3 dp, unchanged) and the seasonal entry.
P2 The three M373 producers use the same mask (`sensitivity_gtr.py`, `simultaneity_gtr.py`: clean = f_gen notna AND canonical; `speed_split.py`: the canonical-clean fuel rows instead of all 261); P2 blocks are re-run on `raw/` (originals) with the M373 runner and re-spliced; sensitivity BASE must still equal the (new) live headline (known-answer gate).
P3 `gtrClosure` text (M372): the set note and `excludedNote` are regenerated from the sets by script (headline set = canonical-clean 259; the closure excludes only the two NaN-offset drives; the "departure from the canonical-clean rule is an open item" clause is removed because it is closed); the closure numbers do NOT change (its set is unchanged).
P4 Labels: the `refreshedBlocks` status text ("drive set = headline definition (f_gen not NaN ...), not canonical-clean" / "all 261 ...") is regenerated by the splice script from the sets (canonical-clean n of fuel-instrumented n); old wording added to `language_gate.py`; REQUIRED strings in `semantic_gate.py`.
P5 Ripple scan before the build (script-written list): every JSX / payload / test / gate site that states or binds `nProduction`, `nDrives`, "260", "261", "headline definition", "f_gen not NaN" (including the Sankey corpus note and Limitation 7); each is either bound to the payload (no edit) or listed and fixed.
