## 1. Problem (audit section 21, Cs-21)
The Crawl & Stop-Go panel reports `whLaunchOut` (gross discharge-out over the LAUNCH window), `whApproachIn` (gross regen-in over the APPROACH window) and `whCycleNet` (signed net over the whole stop-to-stop CYCLE). These are three different masks (windows), only partly overlapping; the panel never states the windows next to the numbers, and never shows, per window, the signed net and the one-direction energies together. A zero median approach regen (`whApproachIn` median 0.0, while P(any regen) is 0.60 across approaches) can coexist with non-zero events; the reader cannot see that without both views.
## 2. Definitions (from `_csg_events`, unchanged segmentation; STOP = speed < 1.5 km/h sustained >= 3 s; tgt = min(15 km/h, inter-stop peak); cycle = consecutive-stop pair with inter-stop peak <= 30 km/h)
Power p = (-I)*V/1000 kW (M11, discharge-positive); energy over an inclusive 1 Hz index window: net = sum(p)/3.6 Wh (signed); discharge-direction = sum(max(p,0))/3.6; regen-direction = sum(max(-p,0))/3.6 (reported as a positive magnitude); net = discharge-direction - regen-direction exactly. Windows per cycle (e_k = end of the first stop, s_k1 = start of the next stop, lend = first index with speed >= tgt after e_k, abeg = last such index before s_k1):
- launch: [e_k, lend]; approach: [abeg, s_k1]; full cycle: [e_k, s_k1]; creep (new): [lend+1, abeg-1] (empty when lend+1 > abeg-1).
Launch and approach share a boundary sample when lend == abeg; the windows are therefore NOT claimed to partition the cycle; the block reports the share of cycles where launch, creep and approach are disjoint and the sum of the three nets equals the cycle net within 1e-9 (`additiveShare`), and says so.
## 3. Block (per cohort all/warm/shoulder and top level, from the same cycle list as `whCycleNet`, I and V present)
`phaseEnergy` = `{windows: [{key, label, mask}], launch|creep|approach|cycle: {netWh, dischargeWh, regenWh: {median,p25,p75,p95,n}, bootMedian CI for net/discharge/regen via the day-clustered bootstrap used by the file (seed 42, 4000 draws), zeroShare: {discharge, regen} (share of cycles with exactly 0.0 Wh)}, additiveShare, consistency: {launchDischarge == whLaunchOut, approachRegen == whApproachIn, cycleNet == whCycleNet (quantile dicts equal)}, methodology}`.
Existing `crawlStopGo` fields and all other seasonal blocks are untouched (parity: deep-diff allow-list = the new `phaseEnergy` leaves only).
## 4. Display (CrawlStopGo panel, cohort-aware, not in Compare): table "Energy by phase window" with columns window (mask), n, signed net median [IQR], discharge-direction median [IQR], regen-direction median [IQR], share exactly zero; one sentence stating the masks differ and are not additive; the existing KPIs keep their labels plus the window in parentheses.
## 5. Gates
Known-answer unit test on a scripted stop-go grid (hand-computed windows and energies; identity net = dis - regen; creep window; additivity flag); control (existing fields byte-identical, consistency flags true); blind audit (Sonnet, claim + definitions + raw path, no code): recompute launch/creep/approach/cycle net/discharge/regen medians over all drives; semantic gate: required phrases ("Energy by phase window", "not additive"), no "recovery"-style claim beyond existing text; jsdom; post-step idempotence; release_check. Wording: reconstructed/derived from logged current x voltage (asynchronous polling, 1 Hz grid), never "measured energy".

## Rev 2 (Director: "revise"; all accepted)
S1 The "P(any regen) = 0.60" juxtaposition is dropped from the spec and the panel text: it comes from `regenProbability` (standalone approaches list: every stop, 20 s cap), a different list from the cycle windows; the new block reports its own zero shares on the cycle list. S2 Windows are copied from the code with its guards: launch [e_k, min(lend, s_k1)], approach [max(abeg, e_k), s_k1], cycle [e_k, s_k1], creep [lend+1, abeg-1]; cycle windows are NOT capped at 20 s (the cap applies only to whPerLaunch / whPerApproachRegen); after the vpk gate `up` is never empty; lend == abeg arises when only one sample reaches the target (common when the inter-stop peak is below 15 km/h) and gives a shared boundary sample and an empty creep. An empty creep window is EXCLUDED (n reported, nEmpty), never 0; all-NaN windows (None) are counted separately (nAllNaN). `additiveShare` = share of cycles with launch end < approach start; the residual check uses a relative tolerance 1e-9 * max(1, |net|). Per-window grid coverage (share of non-NaN p samples, median) is reported; the dropna means energy over gaps is understated, and ffill(limit=3) makes I*V stale in the source grid (caveat in the methodology). One-direction energies are biased upward by sign-flipping noise (rectification); the net is not. Zero-inflation: 'zero' = value <= 0 (as in M226.1); if zeroShare >= 0.25 the window/direction is reported in the M226.1 two-part form (day-clustered P(>0) with CI and the positive-part median with CI) instead of a pooled median CI; otherwise the day-clustered bootstrap CI of the pooled median. zeroShare is provenance-sensitive (raw/ current is integer-rounded in the re-exports): "raw/ basis, provenance-sensitive (F03)" label; an originals sensitivity is a follow-up. The consistency checks (launch discharge vs whLaunchOut, approach regen vs whApproachIn, cycle net vs whCycleNet) re-run the same `_phase`: regression control only, not validation. Deep-diff confirms the new cycle-dict key `ph` does not leak into `_crawl_stop_go_two_part` or any cohort output. Out of scope, ledgered: the existing panel's 'measured'/'recovers' MetricHighlight tones on reconstructed energies (jsx ~L8976-8995).
