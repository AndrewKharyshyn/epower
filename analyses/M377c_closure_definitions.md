# M377c: written definitions of the generator-node closure diagnostic (for a blind re-derivation; values-free, code-free)

Purpose: independent derivation of the quantities of `generatorTractionRecon.gtrClosure` on the live corpus. The per-drive reconstruction is the SAME as in `analyses/M377b_recon_definitions.md` (sha256 6345350c04dcb592194c5bb793e99cd0720c5d24b0de542a94abaa52e3b0f4e8), sections 2 to 4 (frame, offset, battery power, regimes, BSFC, anchoring, traction power): implement it from that document. This document adds the closure-specific set, columns, totals, interval and verdict rules. It contains no result. Generator and traction quantities are reconstructed / estimated, never measured; alpha* is a labelled closure parameter.

## 1. The closure set
Start from `drive_master.csv` (524 rows) and the raw files in `raw_only/`. A drive is in the closure set when ALL hold: the raw file exists; `ens_outlier_v2` is not True and `distance_km > 0`; the file is fuel-instrumented (fuel-rate column present, header text of the M377b document, section 1); and `I_offset_A_applied`, `charge_eng_only_kwh` and `charge_dual_kwh` are all present (not NaN). Unlike the M377b blocks, a drive whose `I_offset_A_applied` is missing is NOT given the corpus constant here; it is excluded ("no battery inputs"), and the offset used is the drive's own stamped value. Drives for which the per-drive reconstruction returns nothing (fewer than 10 fuel-rate samples) are dropped. Report n drives, n calendar days (distinct `date`), total km (master `distance_km`), the drives that satisfy the fuel and canonical conditions but are excluded for missing battery inputs (IDs and reason), and the closure drives that were NOT in the earlier 257-drive set whose IDs are listed (one per line, no values) in `audit/closure_previous_ids.txt` (IDs of new drives).

## 2. Per-drive columns (kWh unless stated)
From the reconstruction of the M377b document with the scenario central: `E_gen` (drive aggregate generator-bus energy), `g2t` (generator-to-traction energy), `trac` (gross traction energy), `b2t = max(trac - g2t, 0)`. From the master: `eng_only = charge_eng_only_kwh`, `dual = charge_dual_kwh`, `regen = charge_pure_regen_kwh` (missing treated as 0), `km = distance_km`. Derived: `g2b_master = eng_only + dual`; `excess = g2t + g2b_master - E_gen`; `excess_engonly = g2t + eng_only - E_gen`.

## 3. Totals and the generator-node excess
- Per-100-km totals are ratios of sums over the set: `(sum of the column) / (sum of km) * 100` for `E_gen`, `g2t`, `trac`, `g2b_master`, `eng_only`, `dual`, `regen`, `b2t`, `excess`, `excess_engonly`.
- Relative excess: `excess_rel = sum(excess) / sum(E_gen)`; the variant without the dual term: `sum(excess_engonly) / sum(E_gen)`.
- Day-clustered percentile bootstrap (the calendar day is the resampling unit): resample the distinct calendar days with replacement (as many draws of days as there are days), concatenate the drives of the drawn days, recompute the ratio; 4000 draws, seed 42 (any independent implementation with the same unit and draw count is acceptable; compare at the verdict level and with Monte-Carlo tolerance on the endpoints); the interval is the 2.5th and 97.5th percentiles.
- Closure rule: `closed` is true when the 95 % interval of `excess_rel` lies inside [-0.05, +0.05] (lower end >= -0.05 and upper end <= +0.05). Report the estimate, the interval and the flag for `excess_rel` and for the dual-removed variant.
- Strata: per `drive_type` (master), only types with at least 10 drives are evaluated; for one stratum of your choice with n >= 10 (say which) report n, days, the `excess_rel` estimate, its interval and the `closed` flag.

## 4. f_gen and alpha*
- Per drive for this step: `G = g2t`, `L = eng_only`, `dual`, `trac`, `E_gen` as above. `f_gen = sum(G) / sum(trac)` over the set; its 95 % interval by the same day-clustered bootstrap (resample days, recompute the ratio of the resampled sums). Report whether the interval contains 0.5 (`ciContains0p5`) and whether the point estimate is below 0.5.
- Closure parameter alpha*: `alpha_star = (sum(E_gen) - sum(G) - sum(L)) / sum(dual)` (a labelled implied parameter solved from the same data); interval by the same bootstrap (ratio of resampled sums, draws with a non-positive denominator excluded). Also report the number of drives whose per-drive alpha `(E_gen - G - L) / dual` (drives with `dual` = 0 give no value) lies outside [0, 1].
- Interval of the node excess for the lower and upper accounting: `X_lo = G + L - E_gen`, `X_hi = G + L + dual - E_gen` per drive; relative to the generator: `sum(X_lo) / sum(E_gen)` and `sum(X_hi) / sum(E_gen)` (point estimates; report both).

## 5. What to deliver
For the live corpus: the set of section 1 (n drives, days, km, new IDs versus the 257 set, excluded IDs with reason); the per-100-km totals `E_gen`, `g2t`, `trac`; `excess_rel` (point, interval, `closed`) and the dual-removed variant; f_gen (point, interval, `ciContains0p5`); alpha* (point, interval, number of infeasible-alpha drives); the `X_lo` / `X_hi` relative point estimates; one stratum (section 3).
