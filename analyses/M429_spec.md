# M429 spec - day-clustered interval for the parked-soak time constants (audit F06)

Status: PRE-REGISTERED, written before any result of this change exists. Rev 2, 2026-10-14 (Rev 1 reviewed by the research-director: verdict "revise", four blocking items B1-B4, all adopted; changes in section 8). Owner: Andrii. Origin: external audit 2026-10-13, finding F06 ("Pack-soak bootstrap samples adjacent drive pairs as iid, unlike day-clustered engine thermal decay. Use departure/arrival day or contiguous-day blocks; show the resampling unit and censoring/selection support"), triaged in M427; verified in code on 2026-10-14.

## 1. What is wrong (verified on disk)

- `compute_summary_arrays._heat_soak_carryover` (pack, payload `heatSoakCarryover.soakTauCI`, copied into `interDriveCarryover.thermalDecay.battery.tauCI`) resamples the fitted pairs i.i.d. (`rng.integers(0, nfit, nfit)`), 1000 draws. Its docstring and the `interDriveCarryover.methodology` text say "day-clustered bootstrap"; for the pack that is false. The fit has 350 pairs on 97 arrival days (maximum 15 pairs per day, Kish effective days about 69 before any within-day correlation); 58 % of the gaps are under one hour and consecutive pairs share a drive.
- `_carryover_thermal_decay` (coolant and oil, `interDriveCarryover.thermalDecay.coolant|oil`) already resamples whole arrival days (`day = str(ts_full of the following drive)[:10]`).
- All three: 1000 draws (project standard is 4000, seed 42) and `if s < 0` silently DROPS bootstrap draws whose Sen slope is non-negative (no decay), which removes the largest tau values from the percentile set and can only narrow the upper bound.

## 2. Estimand and what does not change

Estimand: the parked-soak Newtonian-cooling time constant tau (h) for pack, coolant and oil, defined as today: Sen's slope of ln(resid excess / init excess) on the parking gap, tau = -1/slope for slope < 0. The point estimates, `tauFitN`, `tauFitR2`, `tauFitIntercept`, gap bins and every other leaf of the three blocks must reproduce EXACTLY before the interval method changes (gate G1). Only the confidence interval method, its count of draws, and its disclosure change. tau stays a model-derived summary with a negative predictive R^2 (audit F05, already disclosed): no cooling time constant is claimed as a property of the pack.

## 3. Method

1. Cluster key. Coolant and oil: the existing `day` of the linked adjacent-drive table, `str(ts_full of the FOLLOWING drive)[:10]` (arrival day). Pack: the pair table inside `_heat_soak_carryover` carries no day key, so it gets the identical definition `str(b['ts_full'])[:10]` (b = following drive), added as a column inside that function; adding it must leave `gapBins` and every other output byte-identical (G1). Arrival day is the primary key because the manual ambient of the arrival drive is the main shared error of a pair and because it matches coolant and oil.
2. Draws. Draw whole clusters with replacement (G clusters), take all fitted pairs of each drawn cluster (with multiplicity), refit Sen's slope, B = 4000 draws, a FRESH `default_rng(42)` for every method (so the order of methods cannot move the primary interval).
3. Interval on the slope scale. `slope_lo, slope_hi = np.percentile(draw_slopes, [2.5, 97.5], method="linear")`. The decay rate is k = -slope (1/h, always finite) and its interval is `[-slope_hi, -slope_lo]`. tau = -1/slope for slope < 0 and +infinity for slope >= 0: the tau interval is `[f(slope_lo), f(slope_hi)]` with f(s) = -1/s for s < 0 and "unbounded" for s >= 0. The upper tau bound is therefore unbounded if and only if the 97.5th slope percentile is >= 0; the share of non-decaying draws (slope >= 0) is reported separately and does not itself decide the rule. If the lower slope percentile is also >= 0 the whole tau interval is unbounded (reported as null with the shares). If the POINT slope is >= 0 tau is null and k with its interval is still reported. Draws with an undefined slope (all gaps equal) are counted and excluded. Half-life interval = ln 2 x the tau bounds.
4. The slope-scale percentile differs slightly from the old tau-scale percentile of retained draws; this is part of the "iid B=1000 as published" versus "iid B=4000" gap in the method table and is stated there.
5. One shared helper `tools/soak_tau.py` used by both producers; known-answer test with PRE-DECLARED pass criteria: (i) planted exponential decay with day-correlated noise, R = 200 replications, B = 300: empirical coverage of the day-clustered 95 % interval for k in [0.88, 1.00] and of the iid-pairs interval below 0.85; (ii) planted no-decay data: upper tau bound unbounded and non-decaying share above 0.2; (iii) the helper reproduces the published old iid interval [9.96, 13.75] when called with the old rule (iid, B = 1000, drop slope >= 0, tau-scale percentile) on the stored pair set.

## 4. Reported (all from one script, all in the payload)

Per fit (pack, coolant, oil): tau, half-life and its interval, decay rate k and its interval, nfit, the number of clusters and the Kish effective clusters PER METHOD, the new interval and its method string (cluster, B, seed, draw rule), the share of non-decaying draws, the leave-one-day-out range of k (a leave-out slope >= 0 is reported as unbounded tau), and a method-disagreement table: (a) the OLD iid-pairs interval (B = 1000, as published), (b) iid pairs with B = 4000, (c) arrival-day clusters (PRIMARY), (d) departure-day clusters, (e) non-overlapping ISO-week blocks (with fewer than about 25 blocks this is a coarse sensitivity and is labelled so). For coolant and oil, (a) is the published day-clustered B = 1000 interval with dropped draws.

- G2 isolation: the deep diff against the current payload may touch only these leaves: `heatSoakCarryover.soakTauCI` (value), `heatSoakCarryover.method` (text), and the NEW leaves `heatSoakCarryover.soakTauCiMethod`, `soakDecayRateK`, `soakDecayRateKCI`, `soakHalfLifeCI`, `soakTauMethodTable`, `soakTauLeaveOneDay`; `interDriveCarryover.thermalDecay.battery.tauCI` (value) and NEW `.tauCiMethod`; `interDriveCarryover.thermalDecay.{coolant,oil}.tauCI` (value) and NEW `.tauCiMethod`, `.decayRateK`, `.decayRateKCI`, `.halfLifeCI`, `.methodTable`, `.leaveOneDay`; `interDriveCarryover.methodology` (text). Nothing else.
- G3 producer/payload identity: after the producer fix, a single-key recompute from the producer (same inputs as the pipeline: the live master, the cached frames, the config ambients) is byte-identical to the spliced payload.
- D1 (reporting rule, not a pass/fail on science), evaluated on the decay rate k (always finite): the headline interval is the arrival-day one. If the departure-day or the ISO-week interval of k differs from the arrival-day interval in either bound by more than 25 % of the arrival-day k-width, or if one method has an unbounded tau bound and another a bounded one, the dashboard states that block result beside the headline ("method disagreement"); it is never tuned to agree.
- No threshold on the width of the new interval exists. A widening is the expected correction, not a defect.

## 9. Deviations and findings recorded after the run (Director ruling 2026-10-14; the spec text above is unchanged)

- Erratum: the pack fit has 98 arrival days and 97 departure days (Kish effective clusters 67.8), not "97 arrival days" and "about 69". No effect on the estimand or the gates.
- Slope-scale versus tau-scale percentile made no difference here (no draw is non-decaying), and the previous rule dropped 0 draws, so the narrowing concern of section 1 did not occur on these data. The unbounded / +infinity rule was exercised only in the synthetic known-answer test.
- Known-answer test (i) with its final design (gap level and day offset shared within a day): empirical coverage of the day-clustered interval 0.935 (criterion 0.88-1.00), of the pair-iid interval 0.58 (criterion < 0.85). A first design with a day offset independent of the gap left the pair-iid interval calibrated (0.965): pair dependence matters when the regressor clusters by day, as the real gaps do; the criteria were not changed.
- Result: the pack interval moves from [9.96, 13.75] h (pairs i.i.d., 1000 draws) to [9.77, 13.93] h (arrival-day clusters, 4000 draws); coolant and oil change only within Monte Carlo noise. The blind audit (analyses/M429_audit.json, scripts in analyses/M429_audit/) reproduced every value with an identical RNG stream; arrival/i.i.d. interval-width ratio 1.08 / 1.02 / 1.07; residual intra-day correlation (ICC) 0.28 / 0.16 / 0.16 (pack / coolant / oil). The agreement of the methods means weak between-day dependence here, not its absence.
- Additions beyond the pre-registered spec (blind-audit finding, Director ruling): the post-hoc gap split at 1 h (leaves `heatSoakCarryover.soakTauGapSplit` and `interDriveCarryover.thermalDecay.{coolant,oil}.gapSplit`, produced by `tools/soak_tau.gap_split`, labelled "post-hoc descriptive, not pre-registered"); the G2 list is extended by those three leaves; the historical "publishedRule" rows are frozen in `analyses/M429_published_rule.json` and never recomputed at ingestion. Finding: 28 % of the pack ln-ratios are exactly 0 (integer-degree temperature logging); pairs parked under one hour show no resolvable pack decay and the pooled pack tau rests on the longer gaps; for coolant and oil the decay is faster over short gaps (a single exponential does not fit all gaps; tau is a gap-mix-dependent summary).
- Cost: the full recompute (trajectories from the frame cache, 3 fits x 5 bootstraps x 4000 draws, gap split) takes about 4 minutes; B stays 4000 for every row (no spec amendment).
- Follow-ups (own specs): a gap-stratified or two-timescale soak model with interval censoring for the y = 0 mass; the i.i.d. bootstrap of the parked standby-draw fit (`_car_off_standby`).
