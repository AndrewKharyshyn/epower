# M464 spec: ingestion stage checkpoints, fast preflight, synthetic grown-corpus test (tooling only)

Status: pre-registered before any code (Rev 1). Scope: new `tools/` code, one flag in `m296_refresh_master_seasonal.py` and `tools/run_ingest.py`, tests. No estimator, gate threshold, payload key or displayed figure changes. Blind audit: Sonnet (`analytical-auditor`), then Director.

## 1. Problem
Ingestion M463 (606 drives) failed three times late in the chain (m296 parity guard vs additive evTraction leaves; regen_v2 study-lock md5 equality; `regen_display.build()` reading stale on-disk blocks). `run_ingest.py` is journaled: a failed gate rolls back the whole tree, so each small fix cost a full 40-50 min rerun (the M463 run spent 497 s in `refresh_master_seasonal` and 458 s in `regen_v2` alone). Workaround used: `--no-journal --from <stage>`, which gives up the rollback guarantee.

## 2. Component A: stage checkpoints (`tools/ingest_checkpoint.py`, flag `--resume` in `run_ingest.py`)
Definitions.
* Data state D(t) = {path: sha256} of the working tree as `release_journal.tree()` sees it, EXCLUDING source files (`.py .js .jsx .sh`; same set as `run_fingerprint.SRC_EXT`) and `tools/ingest_stages.json`. Source and stage definitions are tracked by code hashes instead, so a code fix does not change D.
* Base B = hash(D before the first stage, raw directory listing (name, size), the `XT_*` environment except `XT_RAW_DIR`, Python major.minor).
* Code hash C(s) of stage s = sha256 over: the stage definition (cmd, env, outputs), and the content of the static local-import closure of every repo script named in `cmd` (AST `import`/`from` of modules that exist at the root or in `tools/`, plus string constants that name an existing repo `.py/.js/.sh` file; for a `.sh` script, tokens naming such files). Documented limit: dynamic imports through computed names are not seen; for those, `--resume` is not offered a stage that lists `"resumable": false` in the stage definition (none set at M464).
* Chain key K_i = sha256(K_{i-1}, stage id, C(s_i)), K_0 = B. Post-state P_i = hash of D after stage i.
Behaviour.
1. A full run (no `--only/--from/--skip`; not `--skip-unchanged`) saves, after every green stage, a checkpoint under `runs/.checkpoints/<B[:16]>/<NN>_<id>/`: `entry.json` {id, K_i, C, P_i, delta lists} and the files created/changed by the stage (delta against the previous state; deletions recorded). Only one chain per B is kept (a new run with the same B replaces it; a green full run deletes its chain). A stage whose write set contains a source file or `tools/ingest_stages.json`, or a file above 30 MB, makes its checkpoint non-restorable (the chain ends there; reported).
2. `run_ingest.py --resume` (explicit opt-in; default behaviour unchanged): the journal `begin()` still snapshots the whole tree first. The longest prefix i = 1..k of the stored chain with K_i equal to the recomputed key is restored (files copied atomically in stage order), then the resulting D is hashed and must equal P_k, else the run aborts and rolls back to the journal snapshot (state `rolled_back`, exit 1). Stages 1..k are reported `status: "restored_from_checkpoint"`; stages k+1.. execute normally and are checkpointed.
3. Invalidation: C(s_j) changed -> K_j and all later keys differ -> stage j and everything after re-run; earlier stages stay restored. A change to D (a data file edited by hand, a different raw listing, an XT_ variable) changes B and invalidates the whole chain.
4. Journal and rollback are unchanged: a failed stage, exception or signal rolls the tree back to the pre-run bytes (including a resumed run); checkpoints live under `runs/` (outside the journaled tree) and survive the rollback; `--no-journal` runs neither restore nor save.
5. `status.json` gains `checkpoint: {resumed: bool, restoredStages: k, firstExecuted: id, reason}`. `runs/.checkpoints/` is git-ignored with the rest of `runs/`.
Acceptance: restored prefix reproduces the same tree hash as executing it (known-answer test with a toy chain); editing stage j code invalidates exactly j.. ; editing a data file invalidates all; a post-restore failure rolls back to the pre-run tree hash; `--resume` with no chain behaves as a normal run.

## 3. Component B: fast preflight (`tools/ingest_preflight.py`)
Runs in a SANDBOX copy of the working tree (journal tree set; `raw/`, `runs/`, `.git`, `node_modules` and `regen_cache/` are not copied; `XT_RAW_DIR` points at the real raw directory). The sandbox stages its own `raw_only/` with `tools/stage_raw.py --raw-dir <real raw>`, so the post-`ingest_core` master is what the checks see. The only shared state is `regen_cache/` (content-keyed by raw-file SHA-256 and extractor/policy hashes), linked into the sandbox (symlink, else Windows junction) so a warm cache is used and any cache fill is idempotent; this is the single allowed write outside the sandbox and is reported (`sharedCaches`). The report states `wroteReal` from the tree hash before and after (tree = journal set, cache excluded).
Checks, on the post-`ingest_core` state:
* `m296`: `m296_refresh_master_seasonal.py --dry-run` (new flag: stops after the parity guard, before any write and before `m295_payload.py`). If `seasonal_drive_master.csv` does not cover the master (state right after `ingest_core`), the sandbox first runs `compute_seasonal.py` there.
* `regen_v2`: `tools/regen_v2_stage.py --dry-run` (existing flag; includes the lock checks and `regen_display.build(arrays=N)` gates).
* Not included: `leaf_guard`/`restamp` (they judge the output of the whole chain, which does not exist after `ingest_core` alone; the lost-leaf risk of `carry_forward` is covered by component C).
Output: JSON `{checks:[{id,status,seconds,detail}], sandbox, wroteReal:false}`; exit 0 only if every check is `ok`. Verifies that the real tree hash before == after. Thresholds and gates are not touched.

## 4. Component C: synthetic grown-corpus test (`tests/synthetic/test_ingest_grown_corpus.py`)
Builds a sandbox copy of the repository with a reduced corpus (every 20th row of `drive_master.csv` and the matching `seasonal_drive_master.csv` rows) plus ONE synthetic new drive (a clone of the newest row under a new file key; its cohort label and its `ah_throughput.csv` sidecar row cloned as the ingestion stages would add them), rebuilds the top-level blocks that m296 compares with the same builder functions the ingestion uses (`compute_summary_arrays.category_A`, `_energy_path`, `_soc_level_sensitivity`, on the exposure-basis frame), re-attaches the previous arrays' additive leaves with `ingest_core.carry_forward` exactly as at a real ingestion, and requires `m296_refresh_master_seasonal.py --dry-run` to pass (M463 failure (a)). Negative control: a changed shared leaf must still fail the guard. The test is a guard-glue test: the numbers are not compared to published values. Unit tests of components A and B: `test_ingest_checkpoint.py` (end-to-end on a toy chain through the real `run_ingest.py`), `test_ingest_preflight.py`. All three are added to `.github/workflows/ci.yml`.

## 5. Out of scope
Making stages faster; changing stage order; `--recompute-m119v2` pass-through; the M464 data refresh list in the memory notes (separate milestone).

## 6. Rev 1.1 (after the blind audit, before the Director decision)
Audit findings applied (tooling only): (B1) a stage flagged `"rerun_on_resume": true` in `tools/ingest_stages.json` is re-executed after its restore without invalidating later restored stages (set for `stage_raw`: `raw_only/` is outside the data state); other excluded caches (`capacity_cache`, `raw_cache`, `drive_raw_cache`, `regen_cache`) are content-keyed caches, not stage state. (B2) the code hash also follows bare string constants naming a repository module (`__import__('mod')`, `import_module`); `"resumable": false` on a stage ends the chain at that stage (implemented). (B3) checkpoint construction is inside the journaled try block. A `CheckpointError` discards the chain. The preflight gains `--with-ingest-core` (the real tree is at the pre-ingestion master after a journaled rollback) and documents the precondition.
Documented limits: git HEAD is not part of the base key (a fix is normally committed between a failed run and `--resume`; `leaf_guard --previous git:HEAD` and `m321 update` read HEAD, so a HEAD change that matters to them needs a full run); raw content is represented by the raw listing (name, size) plus `raw_manifest.json` in the data state (new files change the manifest); a plain full run without `--resume` replaces the stored chain for the same base state; `wroteReal` covers the journal tree only (the cache link is reported separately); a computed-path read of a documentation file is not seen by the static code hash.

## 7. Rev 1.2 (Director decision: accept with conditions)
Applied in code: the base key now also hashes the git blobs of `summary_arrays.json`, `summary_config.json` and `drive_master.csv` at HEAD (a code-only commit between a failed run and `--resume` keeps the chain; a changed committed data file drops it), the raw listing as (name, size, mtime_ns), and the numpy/pandas/scipy/scikit-learn/statsmodels/rainflow versions (supersedes the Rev 1.1 limit on HEAD and raw). Conditions carried to the first production use: (1) targeted Sonnet re-check of the Rev 1.1 fixes; (2) one real-corpus no-new-drive check (full run versus resume from a midpoint, identical data state except declared stamp fields) recorded before the first production `--resume`; (3) any ingestion that uses `--resume` states it in its CHANGELOG entry with the restored stage ids and the `status.json` checkpoint block (`release_check.py` still runs on the final state). M464 is not a gate and changes no figure; default `run_ingest.py` behaviour is unchanged except that checkpoints are saved.
