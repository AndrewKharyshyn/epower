## 2. Definitions (frozen by this spec)
- Freeze timestamp F = 2026-11-17T19:01:29+02:00, the commit time of the freeze (`f7b5014`, CHANGELOG M717). Drive start times in the exposure frame are the logger clock, assumed Europe/Kyiv local time; a drive that starts within one hour of F on either side is excluded from every set below (clock ambiguity).
- Scoring set (operationalisation of the freeze, no band or prediction changed): drives that start after F (+1 h). Drives dated 2026-11-10..16 form a separate stratum "post-basis, pre-freeze", reported beside and never primary. The frozen basis (through 2026-11-09) is never scored.
- Per-prediction trigger variable and support (support rule of the freeze: at least 10 drives (pairs) on at least 5 days, else "not evaluable"; a fixed temperature window is a pre-registered operationalisation, not a new cell): P1 and P2: winter restart pairs and the realised ambient (the restart-pair and ambient definitions of the freeze file); P3, P4 and P6: probe readings with pack temperature in the fixed window [-5, +3] C (the P4 envelope at -10 C: readings below -5 C); P5 and P7: ambient below 20 C, matched to autumn as in the freeze file.
- Overlap and extrapolation: the temperature range of the frozen basis (lowest probe minimum 1.0 C; the ambient range of the frozen basis, script-written by the monitor). A scored cell inside that range is labelled "out-of-sample in time, interpolation check"; a cell below it is reported separately as the extrapolation test. The freeze's own status text "before the first winter drive" is disputable (15 drives with a probe below 10 C are in the basis); the disclosure above replaces it: P1, P2, P4, P5 and P7 are partly in-sample in temperature.
- Event E1 "first sub-zero pack reading": a drive with at least 10 grid samples (the 2 s pack-probe grid of M638) below 0 C whose probe resolution check (GateA2 / signal_representation) passes; a single sample is flagged only. E1 triggers the refit as a NEW VERSION (v2) per the freeze file, scored after v1; a v2 refit is a new-analysis spec with a blind audit.
- Event E2 flag "post-F cold drive": a drive after F with a pack-probe minimum below 5 C (a monitor flag only, not the definition of the scoring set).
- Event E3 "live refit after F": every ingestion (scenario_refresh); not a violation, scoring never reads live files.

## 3. Guards
G1 (read-only). `tools/guard_paths.py` also blocks Edit / Write on `analyses/M717_frozen_sources/` and `analyses/M717_winter_predictions.json`; a CI-listed test asserts the freeze file sha256 equals the CHANGELOG record, each frozen copy equals its sha256 in the freeze file, and `index.json` covers every source whose live file differs. A deliberate new version is a new file name, never an edit.
G2 (scoring reads only the freeze file). A new tool `tools/winter_score.py` (fails closed): it loads ONLY the freeze file and the frozen copies named by `index.json` (sha256 verified), refuses any live path, scores only the cells above, takes the observed drive master as input, prints "not evaluable" (no number) for a cell below the support rule, and labels interpolation-check and extrapolation cells separately. Known-answer tests on synthetic data: a planted prediction inside / outside its band, a cell below the support rule, a live path refused, a tampered frozen copy refused, a drive inside the F +- 1 h window excluded.
G3 (exposure monitor, report-only). A new ingestion stage `winter_exposure_monitor` (after `scenario_refresh`) writes `analyses/M717_winter_exposure_log.json`, one record per ingestion: master MD5, n drives, hours below 0 / 5 / 10 C (total and after F), counts of drives after F with a probe minimum below 5 C and below 0 C, the coldest probe minimum and date, the temperature and ambient range of the frozen basis, the support counts per prediction cell, and the event flags. It counts exposure and support ONLY, never a prediction metric (no early peeking); it never changes a payload number and never stops an ingestion. `tools/delta_report.py` lists E1 and E2 in its report-only section (E1 routes to the Director and is reported to Andrii).
G4 (contamination record). At E1 the CHANGELOG entry states which live source files include sub-zero data, that the frozen copies do not, and that the refit is a new version; the first scoring look uses the freeze file only.
G5 (code freeze). The sha256 of `tools/winter_score.py` and the definitions above (the fixed window, the exclusion version, the P5 matching bins) are recorded in the CHANGELOG entry of this milestone BEFORE the first E2 event; a later change creates a new scoring version, never an edit.

## 7. Post-implementation record (appended; sections 1-6 unchanged)
Stated deviations from Rev 2, found while implementing: (i) the extractors of the observed quantities of P1-P7 (restart pairs, probe-window resistance ratio, limit-register samples, matched autumn-winter Ah per km, engine-on slope) are NOT implemented in `tools/winter_score.py`; every cell answers 'not evaluable (extractor not frozen)' until they are specified, audited and frozen in a follow-up milestone, so G5 (code freeze) is satisfied for the framework only and the extractor freeze is still owed BEFORE the first scoring look; (ii) the G3 support count for P3, P4 and P6 uses the per-drive probe minimum inside the window [-5, +3] C as a proxy for 'probe readings in the window' (the exposure frame has per-drive minima and 5 C bins, not window hours); (iii) P1 and P2 support (restart pairs, realised ambient) is not counted by the monitor (reported as null); (iv) the ambient range of the frozen basis reaches -1.0 C (driver-recorded drive-mean ambient), while the coldest pack probe reading is 1.0 C: the ambient-based predictions P5 and P7 are therefore already in-sample in ambient down to about -1 C, and only the pack-temperature predictions are untouched below 1 C.
(v) Director decision (accept, M726): a blocking trigger is in the code: `winter_score.extractors_frozen()` requires `analyses/M726_extractor_registry.json` (sha256 of every extractor module) whose own sha256 is recorded in the CHANGELOG; without it no cell prints a number. `tools/delta_report.py` flags a cell that reaches the support rule while the extractors are not frozen (routes to the Director). The freeze-wording correction: the freeze file (unedited) says 'before the first winter drive'; the correct statement is 'frozen after drives with a driver-recorded drive-mean ambient down to -1.0 C and before any sub-zero pack-probe reading'; P5 and P7 above -1 C ambient are 'out-of-sample in time, interpolation check'. The extractor milestone (specification, blind audit, freeze; built and tested on synthetic or frozen-basis data only, never on post-F observations) is owed before the first scoring look and before any cell reaches support.
