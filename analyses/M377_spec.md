## 2. Plan
P1 Label splices as one ingestion stage `post_splices` (after `post_steps`, before `build_html`): `m361_splice.py`, `m362_splice.py --splice`, `m363_splice.py`, then restore `fuelAnalytics.fuel12.m366Shift` from the committed arrays through a small allow-listed tool (frozen historical record, additive, deep-diff asserts only that key changes). Each tool is already guarded (deep-diff, idempotent); the stage fails on any guard refusal. Test: running the stage twice leaves `summary_arrays.json` byte-identical (idempotence), and on the committed M375 arrays it is a no-op.
P2 GTR-family refresh as an ingestion stage `gtr_family_refresh` (after `refresh_gtr_headline`): (a) `m373_point.py --point O --tag M377` (frozen gates unchanged; the stage-former dependency is removed for point O); (b) a new generalized `tools/gtr_family_refresh_splice.py` that replaces the values of `sensitivity`, `simultaneity`, `speedSplit` (row key sets must equal the previous ones), rebuilds `refreshedBlocks` (milestone of the original basis kept, `rerunMilestone` = the ingestion milestone, nDrives / nDays script-written, source hashes), rebuilds `gtrClosure` through `gtr_closure_block.py` under the M372 pre-registered stop rules, and updates `eligibilityAlignment.{current, nFuelInstrumentedRows, excluded, note counts}` while freezing `previous`, `changedFields` and the P_aux-low sentence as the M375 record; (c) deep-diff allow-list: only those keys (and the three seasonal GTR entries already refreshed by `refresh_gtr_headline`) may change; anything else is a STOP.
P3 Stop rules for the stage (so a routine ingestion needs no Director unless something moves): any gate failure of the runner; any reading flip (sensitivity f_gen >= 0.5 on any axis; speedSplit f_gen decreasing from 20-60 to 90-120; simultaneity urban gen+battery-discharge >= highway or urban charge-and-drive <= highway); any change of a row key set; a closure stop trigger (M372 rules). Value moves caused by new data are expected and are reported in `delta_report.json`, not gated by the M373 provenance tolerances (those were provenance tolerances for a raw swap, not for new drives); a move of a headline-type quantity outside its previous CI follows the existing delta-report escalation.
P4 `crawlStopGo.phaseEnergy.blindAudit`: carry the record as a labelled historical record (new fields `basis`: "audit reproduced the M356 corpus, not the live corpus", `basisNDrives` from the record's date, added by script) rather than as a statement about the live numbers; the JSX heading keeps "Blind audit (own resampling, reported not tuned)" and states the audited basis. Display change; Director string review.
P5 `semantic_gate.py`: `nCanonical == 489` -> equal to the live `drive_master.csv` row count and to `len(manifest canonical)`; `formerReexportsReplaced == 333` stays.
P6 Lost-leaf guard (new tool `tools/leaf_guard.py`, stage after `post_splices` and `gtr_family_refresh`): lists every leaf path present in the previous arrays and absent in the new ones, classifies each as expected (data-dependent null-out, listed rule) or unexpected, and FAILS on unexpected. The M376 diff showed the pattern (44 + 149 + 12 leaves silently lost); the guard turns it into a loud failure for the next one-off splice.

## 3. Pre-registered controls (frozen before any code)
(a) Known-answer / no-new-drive control: with the M375 inputs (committed HEAD master of 489 drives, HEAD `fuel_recon_master.csv`, `raw_only` restricted to its 489 keys) the new stages reproduce the committed M375 blocks (`sensitivity`, `simultaneity`, `speedSplit`, `gtrClosure`, `eligibilityAlignment`, `refreshedBlocks` values) with zero leaf differences apart from the allow-listed provenance fields (rerunMilestone, source hashes). If this control cannot be staged, the fallback is: two runs on the 524 corpus are byte-identical, and BASE == live headline, validation counts and identities pass. (d) `release_check.py` green on the M376 branch after the stages (the actual acceptance criterion) and CI `release-gate`.
