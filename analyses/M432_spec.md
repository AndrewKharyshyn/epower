# M432 spec - detector-sensitivity range for the engine-off distance share (audit F04)

Status: PRE-REGISTERED, written before any result of this analysis exists. Rev 2, 2026-10-14 (Rev 1 reviewed by the research-director: verdict "revise", six blocking items B1-B6, all adopted; changes in section 8). Owner: Andrii. Origin: external audit 2026-10-13, finding F04 ("Nearest alignment and symmetric short-run debounce do not guarantee an upper bound on EV time or distance. Call this an estimated RPM-defined engine-off share, disclose two-sided detector/tolerance sensitivity"; "Use an estimated RPM-defined share plus detector sensitivities: threshold, sample age, debounce, forward/backward alignment and coverage. Compare on common support and separately list support gained/lost. Missing RPM must remain UNKNOWN, never automatically OFF. An uncertainty envelope over these conventions is a sensitivity range, not a probabilistic confidence interval."). The wording half was done in M427; this milestone supplies the range.

## 1. Question and estimand

How much does the released engine-off distance share (`evTraction.evPctDistance` = 35.4 %) move when the engine-state detector conventions are changed within a declared, defensible range?

Population and anchor (named before any result). S0 = the released setting. The population P0 = drives with `ev_valid` AND NOT `ens_outlier_v2`, with `_as_bool` semantics exactly as `_ev_traction` applies them (the 7 drives with a NaN `ens_outlier_v2` are KEPT): payload `nValid` = 483, `kmValid` = 9036.4, `evKm` = 3202.8, `evPctDistance` = 35.4 (3202.8 / 9036.4 = 35.44 %). (A recomputation over `ev_valid` alone, without the outlier exclusion, gives 484 drives and 35.466 %; that is a different population and is not the anchor.) Gate G1 reproduces `nValid`, `kmValid`, `evKm` and `evPctDistance` exactly.

Estimand: `share_v(P) = 100 * sum(ev_dist_km_v) / sum(distance_km)` over a drive set P, recomputed under each detector variant v. For each variant the reported quantities are three pieces in percentage points that add up to the total change of the variant's own-support share against S0:
- support lost: `share_0(C_v) - S0`, with `C_v` = drives of P0 that are also valid under v (shows whether the effect measured on `C_v` can be carried back to P0);
- detector effect: `Delta_v = share_v(C_v) - share_0(C_v)`, the PAIRED difference on the drives valid under both settings (this is the quantity the range is built on);
- support gained: `share_v(P_v) - share_v(C_v)`, where `P_v` = drives valid under v (not in P0 if they were excluded; the outlier exclusion is applied to both).
Sum = `share_v(P_v) - S0`. The detector-sensitivity range is `[S0 + min Delta_v, S0 + max Delta_v]` over the comparable variants. It is a range over declared conventions, not a probabilistic confidence interval, not a bound on the true share and not a combination of intervals; the day-clustered sampling interval of the released share is reported beside it, never merged. Min and max carry no interval and no significance language.

Not an estimand: the zero-fuel (motored-engine) definition of "electric" (needs the fuel PID subset and a different population), any change to the released gates, or any physical claim about the controller.

## 2. Verified facts (disk, 2026-10-14)

- Definition (`compute_drive_summary_v6._ev_metrics`): EV state = engine RPM known and `eng_rpm <= 400`, aligned to a 1 Hz grid by `merge_asof(direction='nearest', tolerance=ENG_ALIGN_TOL='3s')`; the debounce input is `known & (rpm <= 400)`, so an UNKNOWN second counts as ON inside the debounce; `_ev_debounce(state, 3)` replaces every run shorter than 3 samples by the previous state, and the FIRST run is exempt (`a > 0`); only afterwards `& known` removes the unknown seconds from the off state, so an unknown second is never counted as off. `ev_dist_km` = integrated speed distance on the off seconds x the odometer scale `k`. Gates: RPM and speed grid coverage >= 0.95, median RPM poll <= 2.0 s, odometer >= 1.0 km, `k` in [0.90, 1.10]. This debounce-input convention and the first-run exemption are held FIXED in every variant.
- The same ENG_ALIGN_TOL is applied to the speed channel in the released code; this study varies the RPM (engine-state) alignment ONLY and holds the speed integration, the odometer scale `k` and the distance denominator fixed.
- RPM polling: median per-drive interval 1.27 s (5th-95th percentile 0.76-1.90 s; 177 drives in the fast era below 1.0 s). For a NEAREST alignment with tolerance tau and a poll interval p the covered fraction of grid seconds is about min(1, 2 tau / p); for a ONE-SIDED alignment (backward or forward) with tolerance tau it is about min(1, tau / p). At tau = 0.5 s only about 31 % of drives keep 95 % coverage for nearest, at 1.0 s about 97 %; a one-sided 1.0 s window fails coverage by construction.

## 3. Variant grid (declared before any result)

Axes (the released value is starred):
- T, RPM threshold for "engine off": {100, 200, 400*, 800} rpm (100 and 800 are the off/on thresholds of the M119-v2 detector; the motored-unfuelled state is far above all of them).
- A, nearest-alignment tolerance (s): {1.0, 1.5, 3.0*}; 0.5 s is evaluated only as a one-at-a-time row labelled "support collapse, not comparable".
- D, alignment direction: nearest* (window +-A); backward and forward at MATCHED WINDOW WIDTH (one-sided tolerance 2A, so 2.0 / 3.0 / 6.0 s) so that the direction is not confounded with the window width. Backward at the SAME numeric tolerance (one-sided A, window width A) is an additional one-at-a-time row ("sample age"), labelled as a narrower window.
- B, debounce (samples, 1 Hz): core {0 (none), 2, 3*, 5}; B = 10 is a one-at-a-time STRESS row (a minimum-run filter, not a debounce convention) outside the factorial.
- G, coverage gate (RPM and speed): {0.90, 0.95*, 0.98}; a support stress row (one-at-a-time) outside the factorial.

Designs and the headline (named now): the PRIMARY result is the set of ONE-AT-A-TIME `Delta_v` ranges per axis around S0 (per-axis range, including the 0.5 s, the same-tolerance backward, B = 10 and G rows, each flagged as comparable or not). The FULL FACTORIAL over the core grid T x A x D x B (4 x 3 x 3 x 4 = 144 cells, matched-width directions) is a secondary "joint outer envelope"; B = 10, G, the 0.5 s row and the same-tolerance backward row are stress rows outside it. The cells that reach the minimum and the maximum of the factorial are named in the output.

Comparability rule (declared planning choice, B4): a variant enters the factorial / the headline range only if `C_v` keeps at least 90 % of the P0 drives by count AND at least 90 % of the P0 distance (km); the days kept are reported; the others are listed as "not comparable (support collapse)" with their counts. For every variant the table reports the three pieces of section 1, the drives valid under it, the days kept and the unknown-RPM share of grid seconds.

## 4. Uncertainty

- Sampling uncertainty of the RELEASED share: day-clustered percentile bootstrap (cluster = calendar day, B = 4000, seed 42, ratio of per-day sums) on P0; n drives, n days and the Kish effective days are reported. This interval is stored only inside `evTraction.detectorSensitivity`; `evPctDistance` and the rest of the block stay untouched.
- Sampling uncertainty of each one-at-a-time `Delta_v`: the same day-clustered bootstrap on the paired per-day sums (numerator `ev_v - ev_0`, denominator distance over `C_v`).
- The range itself is deterministic given the data and is never given an interval or merged with the sampling interval. Variant results are not tuned or selected; the range is the min and max of the declared comparable set.

## 5. Gates and tests

- G1 parity: the evaluator at S0 reproduces the master `ev_dist_km`, `ev_time_s`, `ev_cov_rpm`, `ev_cov_speed` and `ev_valid` for every drive (to the stored rounding: 3, 0, 4, 4 decimals; `ev_valid` exactly) and, on P0, `nValid`, `kmValid`, `evKm` and `evPctDistance` of the payload exactly; a mismatch stops the run.
- G2 isolation: one ADDITIVE payload key `evTraction.detectorSensitivity` (deep diff: nothing else changes) plus the dashboard text bound to it.
- G3 identity: a single-key recompute from the tool is byte-identical to the spliced leaf.
- Known-answer tests (criteria declared here) on synthetic RPM / speed series with a planted engine schedule: (i) an exact 1.0 s series with runs of at least 3 s: S0 recovers the planted share to 1e-9 and every direction / tolerance variant agrees; (ii) planted 2 s ENGINE-ON bursts inside an off run: debounce 3 absorbs them (the share rises by exactly the burst distance), debounce 0 keeps them; (iii) planted 2 s OFF flickers inside an on run: debounce 3 absorbs them (the share falls by exactly their distance), so the debounce can push the share either way (the F04 point); (iv) coverage: samples at 0.2 + 1.5 k s (a fixed phase) with a nearest tolerance 0.5 s cover 2 of every 3 grid seconds (coverage 0.667 < 0.95), so the drive is invalid and unknown seconds are never counted as off; and the inclusive boundary is tested on its own (a sample exactly at the tolerance distance IS used); (v) backward versus nearest on a planted step moves a boundary by at most one poll interval, with the hand-computed sign and the matched-width one-sided tolerance; (vi) real-data parity of the evaluator at S0 against `_ev_metrics` on 10 raw drives chosen by a declared rule (the 5 fast-era and the 5 slow-era valid drives with the smallest `sha256("432|" + file)`); (vii) unknown RPM gaps shorter than 3 s inside an off run, and at the edge of an off run (including the first-run exemption): the debounce input treats unknown as ON, the off state is intersected with `known` afterwards, hand-computed expected distances.

## 6. Outputs, wording, process

Tool `tools/m432_ev_sens.py` (per-drive variant evaluation from the staged raw files reusing the v6 helpers `_prep_bytes`, `_series`, `_ev_debounce`; writes `analyses/M432_result.json` and the per-drive per-variant table for the blind audit); additive leaf splice `tools/m432_splice.py`; one dashboard sentence and a compact table beside `evPctDistance` bound to `S.evTraction.detectorSensitivity.*`; semantic-gate checks; CHANGELOG M432. Wording: "estimated RPM-defined engine-off share"; "detector-sensitivity range over N declared conventions (k comparable); not a confidence interval, not a bound on the true share"; "paired difference on the drives valid under both settings"; "support gained / lost"; label "raw/ = sha256-verified originals (M366)"; never "+/-", "uncertainty of", "robust", "insensitive", "measured", "validated", "bound", "true share". The study is on demand (re-run when the detector, the gates or the polling regime changes, or after +14 calendar days of new drives); each ingestion carries only a staleness label. No article use.

Process: spec -> research-director review -> implementation and known-answer tests -> run -> validation chain -> blind analytical-auditor (claim + data path only) -> research-director ruling -> dashboard rule, commit, PR.

## 7. Out of scope

The zero-fuel variant; changes to the speed-channel alignment, to `k` or to the odometer repair; the eligibility gates other than the coverage gate G; the run-length histogram and the unassisted subset (they depend on the same detector but are not the headline); a refit of any model.
