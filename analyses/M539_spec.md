## 1. The rule
Engine-on = logged engine speed rpm > 400 on the pipeline 1 Hz grid (native-row ffill 15 rows, grid ffill 15 s, negatives dropped, NaN = not on). Engine-off = rpm <= 400 or missing. Strict boundary everywhere. The 300-400 rpm band is reported separately as "low-rpm rotation band (logged rpm)" (seconds with 300 <= rpm <= 400 are not engine-on under this rule; the band is never called off-time or artefact). Hold limits are defined in seconds in any new code. Separate names that never migrate: generator-active (reconstructed Pgen > 0), engine-start detector (> 300 run >= 2 s: see wave 3) and trigger (> 800 after <= 100), event classifiers (> 1200, > 2000), the regeneration engine-off proxy (<= 300, decision (g)).

## 2. Waves (order; each its own spec)
- **Wave 1 (this programme's first PR, no number changes): the shared constant and the labels.** One module constant for the engine-on rule (name, threshold, boundary) read by the new code; the inventory sites that already use 400 (`engine_on_pct`, EV state, engineRuntime, rpmSyncPoint, GTR interval, capacity_basis, fuel_analytics2) are verified to use strict > 400 (engineStateMachine uses >= 400: handled in wave 4); a test that greps for new bare thresholds. No payload value changes.
- **Wave 2: the rpm-histogram family on the 1 Hz grid.** `rpmDistribution` gains an additive 400 edge (display bins keep their meaning; the [300, 400) band becomes its own bin; engine-off bin = rpm <= 400 or the existing [0,300) plus [300,400) split is kept so both views derive from the same counts); `engineOnThresholdRpm` 300 -> 400; the dependent sidecars and blocks (rpmOptBand, rpmModeCentres, motoredShare denominators, rpmFinding labels, GTR/regen consumers of the histogram) are recomputed or spliced additively with deep diff and delta report; the stored faithfulness gates updated to the new edge (not weakened). Expected, from M536 evidence: engine-on hours -1.587 h (-1.59 %), rpmOptBand +1.02 pp (inside its previous interval); anything else is reported by the delta report.
- **Wave 3: native-cadence and per-speed blocks.** engineOnBySpeed (row-count basis, > 300), turbo blocks (rpm > 300), engine-start rate (> 300): migration or a documented separate name per block, decided in the wave spec from a what-if (start-rate counts are NOT assumed to be unchanged).
- **Wave 4: boundary and the 400-family polish.** engineStateMachine `off` boundary >= 400 -> > 400 (0.015 h in the corpus); one test that every site uses the same boundary.
- **Wave 5: language and display.** Rule(s) in `language_gate.py` for the old wording ("rpm >= 300" as engine-on) with ledger ids; display wording names the rule once per tab; CHANGELOG, dashboard change rule.
