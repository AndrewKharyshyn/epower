1. TAB. Add a top-level tab "fuel" (tab list in xtrail_summary.jsx, dump_tabs.js TABS, tests). Cohort selector and Compare are the global ones (F2.2).
2. CONTENT of the Fuel tab, in order: (a) Fuel basis banner generated from the payload block `fuelContract` (below); (b) GeneratorTractionRecon (moved as is; GTR accounting gate and test unchanged except the tab it lives in); (c) SocBalancedFuel (moved; observed figure first, corrected value labelled scenario, literals removed, basis disclosure); (d) ThermalFuelPenalty (moved; renamed to an adjusted fuel-rate association, no "penalty"/"cost in fuel"/measured badge, key names unchanged). 3. CASCADE. Each Fuel chart implements its Compare entry or carries the all-data badge (F2.4); ThermalFuelPenalty keeps its Compare entry; Cold stays suppressed.
4. FUEL CONTRACT BLOCK (new payload key `fuelContract`, additive, script-written, recomputed every ingestion): produced by `tools/fuel_contract.py` from (i) raw/ headers of the canonical drives (columns by exact name set: counter "Використане паливо(загальний) (L)", rate "Витрати палива (L/h)", related rate; counted per file, never typed), (ii) fuel_recon_master.csv (n rows, charge-sustaining n, method, date span), (iii) model_constants / the GTR fuelBasis for the E10 constants and the arrays' socBalancedFuel.lhvKwhPerL, (iv) existing payload spans for the accumulator subsets. Fields: coverage {nCanonical, nWithFuelCounter, nWithFuelRate, firstDateWithFuel, byMonth}, gtr {nRows, nChargeSustaining, kmProduction, method}, lhvBases [{name, kWhPerL, where}] and their ratio, subsets {socBalanced:{n, days, span}, thermalPenalty:{n, days, span}}, viewBasis [{view, litresFrom, kmFrom}] (F13.6: counter + speed-integral km vs flow + master km), statusLabels (what is logged/app-calculated, model-derived, scenario). Spliced additively by an idempotent post-pass (like f03_provenance_flag.py); REQUIRED_BLOCKS and stamp updated; stage added to tools/ingest_stages.json.
5. WORDING (language gate rules + REQUIRED): "logged/app-calculated" for fuel rate/counter; "model-derived" for GTR; the corrected SoC-balanced value is a "scenario" (CAP_KWH 2.1 verified:false, eta sweep shown); the thermal view is an "association"; no fuel cost; no "penalty" claim of cause.
6. Registry/tests: chart_registry.json (consumed by nothing, stale) gets the tab field of the three moved charts updated and a note; if that proves misleading it is declared retired in the CHANGELOG (decision recorded, not silent).
