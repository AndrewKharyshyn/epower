## Problem (verified on disk, 2026-10-02)
- `GtrFlowGate` (xtrail_summary.jsx) shows the residual table, the non-closure warning and a reveal button in All / Warm / Shoulder mode. In Compare mode `GeneratorTractionRecon` renders `<CompareBlock id="GeneratorTractionRecon"/><GtrSankeyMultiples/>`: the Sankey small multiples are shown by default, WITHOUT the residual table, the warning or the reveal button (probe on the built dashboard: Compare has no `[data-gtr-flow-gate]`).
- The residual arithmetic (generator excess, battery remainder) lives only inside the gate component; the gate's own warning text still calls f_gen "a sensitivity index" (W1 wording: allocation index).
- The release gates check wording but not that the closure residual is visible in every mode, nor that no Sankey renders before the reveal (F14.10, F13.15, F04.r1).

## Design (code + one behaviour change; no number, estimand, payload key or builder change)
1. One pure helper `gtrAccounting(F)` (xtrail_summary.jsx) returns {genOut, genExcess, battIn, battResid, balanced} with the SAME rounding (2 dp) and the SAME 0.05 kWh/100 km tolerance as today. No other place computes these.
2. One component `GtrAccountingTable({cohorts})` renders the accounting rows for one or several cohorts: modelled generator electricity; generator -> traction + generator -> battery = sum; allocation excess over generator output (residual); battery inflow vs battery -> traction; unreconciled battery remainder (residual); closure status; per cohort: n drives, km. Every flow is labelled model-derived / modelled; the fuel row says "logged volume × assumed E10 LHV". The non-closure warning text is shared and says "allocation index" (not "sensitivity index").
3. `GtrFlowGate` (All / cohort modes) renders `GtrAccountingTable` with one cohort + the existing reveal button (behaviour unchanged except the shared text).
4. Compare mode: `GtrSankeyMultiples` renders the accounting table with ONE COLUMN PER SELECTED COHORT (same rows as All mode), the shared warning when any cohort does not close, and puts the Sankey small-multiples grid behind the SAME kind of reveal button, hidden by default ("Show allocation sketches (not conserved flows)"). The Warm − Shoulder difference table stays (it is not a Sankey).
5. Owner decision (CLAUDE.md 2026-10-02) is now satisfied in every mode: the Sankey never renders before an explicit reveal, and the residual is visible without it.
6. Not in this milestone: moving the residual computation to the Python payload (F11.3 second half: needs new payload keys -> own spec with M329), the accounting table's "eligible mask / source boundaries" extra rows (data fields), numeric-x Compare parity (p28.10), assumption-sensitivity panel (M329).
