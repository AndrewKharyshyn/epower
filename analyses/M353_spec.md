## 1. Facts (script-checked)
- The registry entry `i_offset` says "BMS current offset (per drive)", value "fitted per drive (two-pass solve)", class `derived_per_drive`. On disk `I_offset_A_applied` is ONE corpus constant (475 drives, 1 value at 4 dp: -0.3858 A) and `I_offset_2p_A_applied` likewise (-0.3869 A, 475 drives). The offset is stamped only where the SoC-anchored energy residual exists (M349 root cause).
- Its `usedBy` is ["gross/net energy", "GTC"]; compute_drive_summary_v6 (`_v5_postprocess_master`, ev-battery comment ~1496) states the offset is a net-draw correction deliberately NOT applied to gross quantities (gross throughput, GTC). The payload already carries the deterministic sensitivity `energyUncertaintyMC.offsetGrossSensitivity` (offset applied before the discharge/charge split raises gross throughput by throughputShiftPct = 0.3406 %, shift 5.1005 kWh), so the "+0.34 % variant" is bound to that key, not typed.
- model_constants.py has no per-constant class; the registry assigns classes by hand. `FUEL_VOL_ERR` comment says "ECU fuel volume" (the logger is Car Scanner ELM OBD2: logged/app-calculated).

## 2. Changes
1. `model_constants.py`: `CONSTANT_CLASS` (symbol -> class from the registry vocabulary: literature / assumed / policy / derived / measured_external) for the module constants that are model inputs (RHO_G_PER_L, LHV_MJ_PER_KG, FUEL_VOL_ERR, ETA_GEN, ETA_PE, P_AUX_KW, I_OFFSET_SIGMA_A, BSFC_FLOOR, BSFC, COLD_*, ...). `build_assumptions_registry.py` asserts that the class of every registry entry whose symbol is in `CONSTANT_CLASS` equals it (a drift test, no hand duplication) and `test_assumptions_registry.py` gains that test.
2. `i_offset` entry (strings bound to master/payload): label "BMS current offset (one corpus-wide constant)"; value "-0.3858 A on 475 drives (one value; two-pass solve -0.3869 A)" built from `drive_master.csv` / `offsetUncertainty.pointEstimateA`; class `derived_corpus_constant` (new KLASS; jsx label "Derived, corpus constant"; the old `derived_per_drive` key stays in the jsx map, unused); source "M13/M24 SoC-anchored solve, stamped only on drives with a SoC-anchored energy residual; uncertainty sigma 0.15 A carried in Monte Carlo"; usedBy ["net draw (net_draw_kwh_corr, per 100 km)", "corrected energy residual"]; sensitivity "Net-draw correction only: not applied to gross throughput or GTC (released convention).
