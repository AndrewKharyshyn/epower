# M755 spec: ambientByDrive non-canonical entries (66 plain numbers, 3 one-reading lists): normalisation, a whole-config release guard and the leaf-level refresh of the published blocks that skipped them

Rev 1. Committed BEFORE any change to `summary_config.json`, any splice or any code. Author: main session (Sonnet). Number taken after checking the CHANGELOG head (M754), open PRs and the remote branch list. Origin: the pre-existing omission found by the M754 blind audit (recorded in `docs/open_items.md` and the M754 CHANGELOG entry), the Director's ruling that it needs its own milestone (spec, fix, guard test, blind audit, Director), and the owner's instruction "Continue with the ambient fix" (2026-11-23). Next step: Director review of this spec, then the control builds, the leaf-level splice, the guard, the rebuilt dashboard, a blind audit, the Director decision, CHANGELOG, PR.

## 0. What is known (measured; aggregates)
- `summary_config.json` `ambientByDrive` has 717 entries. The standing protocol (`tools/ambient_protocol.py`) defines the canonical form: a list `[start, *interim, end]` of at least 2 numbers; one reading is stored as `[v, v]`. `python tools/ambient_protocol.py check` reports **69 non-canonical entries**: **66 plain numbers** (2026-09-11 07-42-27 to 2026-09-22 21-59-14) and **3 one-reading lists** (2026-08-08: 20260808_122545, 20260808_124714, 20260808_130411, each `[27.0]`). Nothing in a release or CI gate runs `check`; the ingestion static preflight (`tools/ingest_static_preflight.py`, `check_ambients`) enforces the canonical form only for raw files not yet in `raw_manifest.json`, so older entries were never checked retrospectively.
- Five code sites in `compute_summary_arrays.py` read the entries with list-only code: `_heat_soak_carryover` (`sum(float(x) for x in pair) / len(pair)` inside try / except, so a plain number is skipped silently), `_daily_fingerprints`, `_linked_adjacent_drive_table`, `_battery_temp_ranges` (the same pattern) and `_aux_load_ambient` (reads `[0]` only for a list). A one-reading list is handled by all of them; a plain number is dropped by all of them. Published consequence of the 66 plain numbers: the heat-soak block has 593 of 706 pairs with ambient (up to about 659 possible); the other blocks that read these sites lose the same drives.
- The value of each affected entry is a valid single manual reading (the protocol defines it as `start = end`); no value is missing or out of domain.
- The registered M751 (heat-soak contamination) result reproduced the published block on purpose and so carries the same omission; M754 reads a plain number as a valid reading and is unaffected by the normalisation.

## 1. Constraints
- The fix is **value-preserving** on the data side: only the 69 non-canonical entries are rewritten, by the protocol's own `normalize --write` (plain number or one-reading list -> `[v, v]`), nothing else in `summary_config.json` changes (asserted by a deep comparison of every other key and a byte-identical round trip of the rest of the file). No `drive_master.csv` change (MD5 d514d6009d6d9a0a168ad4fb09b9bb98, asserted before and after). No raw file is touched.
- The five code sites are NOT edited (an 18.9k-line file; with canonical data they are correct); the defence is the guard of section 4.
- Published figures that change are changes of BASIS ("66 further drives' recorded ambient is now used"); wording: "omission fixed / coverage extended", never "error corrected" or "corrected" (CLAUDE.md language discipline); every displayed change is listed before and after.
- The change follows the established arrays pattern (M415 / exposure_splice): two control builds on the same master, raw set and sidecars; leaf-level splice only where the published payload equals build A at that leaf; anything else escalates. No `run_pipeline()` for routine ingestion; no ML column changes (ML16 frozen).

## 2. Method
1. **Normalise:** `python tools/ambient_protocol.py normalize --write` on a copy; assert that (a) exactly the 69 keys change and every other key and every other section of the file is byte-identical, (b) for each of the 69 entries the new list's first, last and mean values equal the old reading, (c) all 717 entries are canonical afterwards.
2. **Control builds:** build A with the current config, build B with the normalised config (the same `build_summary_arrays` call as the ingestion core, same master / raw_only / sidecars, `recompute_m119v2=False`, `recompute_energy_mc=True`), written to scratch files; control V0: build A equals the published `summary_arrays.json` leaf by leaf except the leaves the repo already records as run-to-run or carried (any difference outside those stops the tool: "published payload differs from build A: decide per leaf").
3. **Expected-changed set:** the deep diff B versus A. A leaf may change only inside the blocks produced by the five sites (`heatSoakCarryover`, the linked adjacent-drive table and its dependents, `dailyFingerprints`, the battery temperature ranges / battery-versus-ambient lists, the standstill-draw ambient correlation block) and their artifact stamps; a differing leaf anywhere else ESCALATES (exit 1, nothing written). The set of changed keys is written to the result before anything is spliced.
4. **Splice:** the changed leaves of B are written into `summary_arrays.json` only where the published value equals A at that leaf (arrays whose length changes are replaced whole); stamps are re-derived by `tools/stamp_dependencies_apply.py` (the `ambientByDrive` config-section hash changes for the declared dependents).
5. **Seasonal side:** the seasonal pipeline reads the same entries (`compute_seasonal.py`, `seasonal_core.ambient_derived_fields`); a value-preserving rewrite must not change a seasonal derived field: asserted for the 69 entries by calling the derivation on the old and the new form (equal), and the seasonal master is not rewritten.
6. **Dashboard:** `node build_html.js`, `node dump_tabs.js`, semantic gate, jsdom; the content change is shown (SendUserFile render) with the list of `S.*` keys and committed with `xtrail_summary.jsx` (unchanged), `summary_arrays.json` and `cohort_arrays.json` (checked unchanged) per the dashboard change rule.

## 3. Estimands and the before / after report
- For every published leaf that changes: the old and the new value (counts, medians, tau and its interval, fingerprint cluster summaries, ranges), grouped by block; the number of pairs with ambient in the heat-soak block before and after (593 -> expected about 659); the displayed prose that quotes a changed number is checked by the semantic gate (prose equals payload).
- Statistical statements about the heat-soak block (tau, retained fractions) keep their own published method; this milestone changes no method, only the set of pairs that have an ambient. A change of a published conclusion (a flipped decision or an interval that no longer contains its previous point) escalates to the Director before any splice.

## 4. Guard (so it cannot recur)
- `release_check.py` payload / config check: every `ambientByDrive` entry canonical (`ambient_protocol.is_canonical`) and every master drive has an entry; `tests/synthetic/test_ambient_canonical.py` (CI list): known-answer tests of `is_canonical`, `canonical` and `normalize` on planted entries (plain number, one-reading list, shorthand string, out-of-domain value); a test that each of the five code sites yields a numeric ambient for a canonical entry built from a former plain number (the heat-soak pairing on a planted pair table, `_aux_load_ambient` on a planted frame); a test that the real config is canonical.
- The ingestion static preflight stays as it is (new files); the release check adds the retrospective whole-config guard.

## 5. Acceptance and falsification
- Accepted when: normalisation asserts hold; V0 holds; the changed-key set lies inside the expected blocks; the splice changes nothing else (isolation diff); gates pass (semantic gate, jsdom, `release_check`, CI unit list); the blind audit reproduces the heat-soak pair count and the new medians / tau from the master, the raw files and the normalised config without the tool.
- Falsified (the fix is value-preserving and local): any leaf outside the five blocks differs between builds A and B, or any of the 69 readings changes value.
