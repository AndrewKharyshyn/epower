- `generatorTractionRecon.gtrClosure` (M336 diagnostic, M372 refresh on the originals) is carried at the M372 set: 257 drives, 50 days, 1996.2 km (`scope.carriedAtIngestion`, listed in `staleBlocks`, rendered by the existing stale-block line). The headline set is 294 drives.

- Hard-wired to the published baseline: `m372_closure_common.assert_baseline_set` raises unless the eligible set equals the M336 set (IDs, days, km) BEFORE any estimate; `check_raw_originals` requires every closure drive's raw file to match `raw_manifest.json` sha256 (holds for all 524 canonical files).
- M372 pre-registered stop rules (analyses/M372_spec.md Rev 2) for the diff: n / ID-set change; an estimate outside its previous 95 % CI; any bool flag or verdict flip (`ciContains0p5`, `pointBelow0p5AllVariants`, `stopTriggered`, `closed` flags, `zeroInsideAllVariants`); a point-only leaf with relative change above 2 % (absolute 0.002 when |previous| < 0.1); a key-set difference. Under these rules every ingestion that adds a fuel drive would stop on "n / ID-set change" by construction.
- Runtime: about 15 minutes for the two producers (M336 note).

## 2. Plan
P1 Expected-set rule (replaces `assert_baseline_set` in an ingestion mode `--ingest`, outputs `analyses/M377c_closure_*`): the eligible set must be a SUPERSET of the previous closure set (`analyses/M372_closure_perdrive.csv`, later the last committed per-drive file); every previous ID must still be eligible with unchanged per-drive inputs flagged if its raw sha256 changed; the NEW IDs are listed (file, date, km, type) and their count is checked against the master (drives added since the previous set that satisfy the eligibility). Any previous ID missing, or an ID in the new set that is not eligible by the rules above, is a STOP.
P2 Stop rules in ingestion mode: kept as pre-registered except "n / ID-set change" (replaced by P1) and the 2 % point-only rule, which becomes REPORT-ONLY for new-data moves (written to the delta file) with the escalation band: a point-only leaf moving by more than 10 % relative (absolute 0.01 when |previous| < 0.1) goes to the Director. Kept as STOP: key-set difference; any verdict / flag flip; an estimate outside its previous 95 % CI (the new set contains the old one, so the previous CI is the natural check; if it fires, the Director decides whether it is new-data signal).
P3 Stage `gtr_closure_refresh` after `gtr_family_refresh`: runs the two producers in ingestion mode, builds the block, diffs against the carried block, writes `analyses/gtr_closure_delta.json` (n drives / days / km previous vs new, new IDs, per-leaf moves, flag outcomes, band checks) for `delta_report`, and splices through an allow-listed splice (the block, `staleBlocks` without `gtrClosure`, `scope.carriedAtIngestion` removed, the set note regenerated). The M377b disclosure then disappears because the numbers are on the live set.
P4 Per-drive file as the next baseline: `analyses/M377c_closure_perdrive.csv` is committed with each ingestion and becomes the "previous set" of the next one (pinned by sha256 in the block `sources`).
P5 Control (a): on the committed 489-drive state, ingestion mode with the previous set = the M372 per-drive file reproduces the committed `gtrClosure` block leaf for leaf (the new-ID list is empty). On the 524 corpus the new-ID list equals the independently derived list (blind audit item).
P6 Blind audit (Sonnet, definitions only, no author code, no values): derive on the 524 corpus the closure set (n drives, n days, km, the new IDs relative to the 257-drive M372 set, excluded IDs with reason), the `E_gen`, `g2t`, `trac` per-100-km totals and the f_gen point estimate (baseline), with a written definitions document in the style of `analyses/M377b_recon_definitions.md` (reuse; add the closure-specific definitions: per-sample generator node, master charge columns `charge_eng_only_kwh` / `charge_dual_kwh`, regen, excess definition). Director decision on the delta report before the PR.

# Rev 2 (Director: revise, required changes applied; FROZEN before any run; the frozen part of this file (sha256 up to the first documentation addendum) is bound into every M377c output)
Rulings. Q1: the expected-set rule replaces "n / ID-set change"; the 2 % point-only rule becomes report-only for moves caused by new data, with the escalation band 10 % relative (0.01 absolute when |previous| < 0.1) to the Director (consistent with M377 Rev 2 Q2); STOP is kept for: an estimate outside its previous 95 % CI, any flag / verdict flip, a key-set change. Q3: acceptable after ONE blind audit of the stage; any ingestion that trips a STOP or an escalation band gets a blind audit and a Director ruling. Q4: audit scope extended (below). Q5 (M377b band unit) confirmed: 0.05 absolute on a 0-1 share = 5 percentage points on the 0-100 scale; speedSplit f_gen stays 0.05 on 0-1; a clarification, not a tolerance change; the wording is stated in the delta files.
